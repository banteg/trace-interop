## 2. Findings

1. **Null for a missing transaction or path (R1–R3) has a real cluster.** Erigon and Reth (native) return null for all three lookups, and Parity's indexed lookups did too. Nethermind's error and Besu/Anvil's `[]` are incidental: a module-wide receipt helper in one case, an `orElse(empty)` fallback in the other.
2. **Missing replay (R4) is the weakest null.**
   - Independent native support is Erigon only. Reth returns null because of this project's PR, although a Reth maintainer accepted it.
   - The error camp (Nethermind -32000, Reth 2.6.0 and Anvil -32001, Parity -32603) does not agree on a code.
   - Parity's error was a bug message.
   - Null stays justified because it is consistent with R2/R3 and with `eth_getTransactionReceipt`.
3. **Unknown single block (R7): an error is the native majority, but not for every method.**
   - `trace_call`: every native client errors.
   - `trace_block`: 3 of 4 native clients error (Erigon, Nethermind, Reth). Besu and Parity return null.
   - `replayBlockTransactions`: 2–2. Erigon and Nethermind error; Besu and Reth return null, and Reth's null is test-locked. Parity errors, but with a pruned message.
   - The matrix has **no case** for R7b. The draft's rule for that method rests on source reading only.
4. **The error code for an unknown block (R8) is where clients converge on something other than the draft.**
   - -32000 comes from Erigon, Nethermind and Besu (trace_call) natively, plus Parity. That is ≥3 native + heritage.
   - -32001 comes from Reth only.
   - The ledger/source-review justification ("matches the newer eth/debug getters, `src/eth/block.yaml:253`, `src/debug/getters.yaml:102`") is **half wrong**. `eth_getBlockAccessList` returns *null* for an unknown block, and upstream debug_trace fixtures use -32000. Only the raw BAL debug getter uses -32001.
   - There is still a concrete caller-side reason for -32001. In `trace_call`/`trace_callMany`, all four native clients already use **-32000 for transaction-validation failures** as well: Erigon "fee cap less than block base fee", Nethermind "maxFeePerGas … < maxPriorityFeePerGas", Reth "invalid chain ID", Besu "Block not found". With -32000, "unknown block" can only be told apart from "invalid call" by parsing the message.
5. **Filter bounds (R9, R10): no native convergence, so the draft may choose.**
   - Beyond the head: four different behaviors. Erigon explicitly waits for a spec. Following eth_getLogs (#875) is justified.
   - Reversed range: every native client errors; the code splits 2–2.
   - **Anvil's -32602 on `a/missing-block-filter` is a false agreement.** The message is "block range too large, currently limited to 300" (0x2f..0xffff), not a bound check. The case page marks it ✅.
6. **Pruned/unavailable state (R12, R13) has no convergence and almost no runtime evidence.** Only Reth is in the matrix. Nethermind deliberately uses -32002 (EIP-1474 "Resource unavailable") for missing state, which is a credible alternative to extending 4444. No client implements R13.

## 4. Proposed text

The recommendation needs no normative change. Two text changes are proposed.

**(a) Ledger H06, "Revised recommendation" background.** Replace "Single-block selectors keep -32001, matching the eth/debug getters." with:

> Single-block selectors return -32001. Only Reth does so today. Erigon, Nethermind, Besu (for the trace_call block) and Parity (for trace_call and replayBlockTransactions, under a misleading state-pruning message) return -32000, and upstream `debug_traceBlockByHash`/`debug_traceTransaction` fixtures also use -32000. `eth_getBlockAccessList` returns null for an unknown block; only `debug_getRawBlockAccessList` specifies -32001. The dedicated code is kept because in trace_call and trace_callMany every native client also uses -32000 for transaction-validation failures, so a caller cannot tell "unknown block" from "invalid call" without parsing the message.

**(b) If the maintainer instead adopts the client cluster**, the recommendation sentence becomes:

> An unknown single selected block (trace_block, trace_replayBlockTransactions, the trace_call/trace_callMany block) returns an error, never null or []; -32000 is used, as Erigon, Nethermind, Besu and Parity already do.

Spec delta for (b):
- `trace-profile.md` L39-41: "-32001 (Resource not found)" becomes "an error (-32000)".
- `methods.yaml` errors for trace_call, trace_callMany, trace_block and trace_replayBlockTransactions: `-32001 Resource not found` becomes `-32000 Invalid input` (EIP-1474 name).
- Case assertions `missing-block-block` and `missing-block-call` change accordingly.

**Also add to next_step:**
- A `trace_replayBlockTransactions` unknown-block case.
- A `missing-block-filter` variant with `toBlock = head+1`, so Anvil's 300-block cap cannot mask the bound check.

## 5. Consequences

- **As drafted (R8 keep):**
  - Erigon, Nethermind and Besu each change a code from -32000 to -32001. Besu and Reth change replayBlockTransactions from null to an error; Reth must update the `http.rs` test.
  - Besu and Anvil change `trace_transaction` from `[]` to null.
  - Nethermind returns null instead of -32000 for missing txs in trace_get, trace_transaction and replayTransaction.
  - Erigon stops returning `[]` for out-of-range bounds.
- **If (b):**
  - Erigon, Nethermind and Besu need no code change for R7/R8. Reth changes -32001 to -32000 in trace_block and the call selectors, and the Geth draft changes too.
  - R4's missing-replay null is unaffected. Reth's release-era -32001 for a missing replay would stay wrong either way.
- **Fix PRs (decisions/fixes.json):**
  - None becomes wrong under keep.
  - [Nethermind #13676](https://github.com/NethermindEth/nethermind/pull/13676) now surfaces "receipt could not be found" (-32000) for a missing tx in trace_get. That is progress (no crash) but still not null, so a follow-up is needed.
  - [Reth #27367](https://github.com/paradigmxyz/reth/pull/27367), [#27378](https://github.com/paradigmxyz/reth/pull/27378) and [alloy-evm #411](https://github.com/alloy-rs/evm/pull/411) assume 4444. They would become wrong only if R12 switches to -32002.
  - [Reth #27364](https://github.com/paradigmxyz/reth/pull/27364) and [Nethermind #13677](https://github.com/NethermindEth/nethermind/pull/13677) are consistent.

The fallbacks are incidental.

## 2. Findings

1. **S1, S2, S5, S6 and S9 have converged** (Besu's gas deviations are tracked under H16 and Besu bugs). No change is needed.
2. **The REVERT CALL result (S3) is a split, not an invention.**
   - Erigon, revm-inspectors (Reth, Anvil) and upstream Geth's flatCallTracer keep `{gasUsed, output}`, each deliberately (explicit branch or comment).
   - Besu, Nethermind and Parity drop it. Nethermind drops data its tracer already receives.
   - Keeping the result preserves nested revert bytes, which the envelope cannot carry. For Besu and Nethermind the change is additive, and Alloy and TrueBlocks already decode both.
3. **The reverted CREATE shape (S4) is a draft invention.**
   - No native client emits `{gasUsed, output}`.
   - Erigon, Reth and Anvil share `{address, code, gasUsed}`, but incidentally.
   - Upstream Geth emits `{gasUsed, code}`, which breaks Alloy.
   - The draft's own justification (a would-be address is misleading) is contradicted at the filter level. Erigon, **Nethermind** and Reth, plus Anvil, all return the reverted CREATE for `toAddress = <would-be address>` ([filter-failed-create-recipient](../../../reports/cases/mined-probes/filter-failed-create-recipient.md), [filter-failed-nested-create-recipient](../../../reports/cases/mined-probes/filter-failed-nested-create-recipient.md), [filter-failed-create-intersection](../../../reports/cases/mined-probes/filter-failed-create-intersection.md)). Only Besu and the Geth draft return `[]`.
   - That is a ≥3-native cluster against **H23**'s "a failed CREATE has no created-address match". Nethermind matches the address without even serializing it.
   - H09's no-address rule and H23 stand or fall together.
4. **"Post-Parity" labels are partly wrong heritage.**
   - Parity implemented EIP-170 and EIP-684 and reported both as **"Out of gas"**. OpenEthereum implemented EIP-3541 as **"Invalid code"**.
   - EIP-170 itself says creation "fails with an out of gas error".
   - Upstream Geth's and Besu's Parity-compat mappings deliberately emit "Out of gas" for the code size limit.
   - The draft already applies the same reasoning to EIP-3860 ("Out of gas, as the EIP specifies"), but not to EIP-170.
5. **Parity's base labels are justified, and no native cluster offers an alternative.** The static-context write has four different spellings. Precompile failures have three. For the invalid opcode, Besu, Nethermind and Parity already agree on "Bad instruction". Reth's divergences are Debug-name fallbacks rather than choices.
6. **`revertReason` (S8) as decoded text is implemented by no trace_* client.** The only implementer (Besu) emits raw bytes, consistent with its receipts. Decoded text adds nothing over `result.output`, and it discards custom-error data.

## 4. Proposed replacement text

**Ledger H09 recommendation** (changed clauses in bold):

> The error field alone determines failure. A REVERT frame has error "Reverted" and requires result {gasUsed, output} with that frame's gas and revert bytes, for CREATE too and never with address or code. An exceptional halt may omit result or set it to null; it consumes the frame's action.gas. Use Parity's failure labels: "Reverted", "Out of gas", "Bad instruction", "Bad jump destination", "Stack underflow", "Out of stack", "Mutable Call In Static Context", "Built-in failed" and "Out of bounds". **As in Parity and OpenEthereum, a code-deposit failure, including code above the EIP-170 size limit, is "Out of gas", and returned code starting with 0xEF (EIP-3541) is "Invalid code".** **Beyond Parity, which reported an address collision as "Out of gas" and emitted no frame for failed prechecks, use** "Contract address collision", "Nonce overflow", "Insufficient balance for transfer" and "Max call depth exceeded". Any other string is an extension that consumers treat as a generic failure. **revertReason is not part of this format; raw revert bytes live in result.output, and a client that emits revertReason must also emit result.** Frame gas follows Parity: …(unchanged).

If the maintainer adopts the client cluster for S4 (option B), and H23 changes accordingly, replace the second sentence with:

> A REVERT frame has error "Reverted" and requires a result carrying that frame's gas and revert bytes: {gasUsed, output} for CALL-family frames, and {address, code, gasUsed} for CREATE, where address is the address the creation would have occupied and code holds the revert bytes, not deployed code.

  - Add a note that Parity reported a collision as `Out of gas`.

Keep the `revertReason: {type: string}` property, since additional properties are tolerated, but drop its semantic sentence. For option B, replace `TraceRevertedCreateResult` (L275-L287) with a reverted variant of `TraceCreateResult`, and update the "Reverted CREATE" `oneOf` branch description (L404-L413).

## 5. Consequences

- **Label changes.** Every client already needs a label map, so the cost is unchanged or lower.
  - Besu can reuse its flatCallTracer `PARITY_ERRORS` map, which already emits "Out of gas" for code size.
  - Reth and Anvil (revm-inspectors) add `CreateContractSizeLimit` → "Out of gas", alongside its other OOG variants, and `CreateContractStartingWithEF` → "Invalid code".
  - Erigon and Nethermind need maps anyway.
  - The Geth draft changes two strings.
  - No client agrees with the current draft strings, so nothing that agrees today is broken.
- **revertReason.** Besu keeps its field as a tolerated extension and needs only S3's `result`. The Geth draft is unaffected; it emits none.
- **S4 as drafted.** Erigon, Reth and Anvil must reshape reverted CREATE results, which is breaking for consumers reading `result.code` or `result.address` there. Besu and Nethermind add the result.
- **S4 option B.** Erigon, Reth and Anvil already agree. Besu and Nethermind add `{address, code, gasUsed}`. The Geth draft and H23 must change: the Geth draft returns `[]` on the recipient filter cases, and Erigon, Nethermind and Reth then become conformant on those H23 cases.
- **Fix PRs.** [Besu #11347](https://github.com/besu-eth/besu/pull/11347) (retain root precompile halt reasons) is unaffected. It must emit "Built-in failed", not "Precompile error", which is unchanged by this proposal. No listed PR touches the create shape or the changed labels, so none becomes wrong.

## Summary

- **H06:** no normative change.
  - Missing tx or path → null (R1–R4) has a real cluster: Erigon, Reth and Parity's indexed lookups. The dissent is incidental.
  - An unknown single block → error has a native majority, but the error *code* does not. Erigon, Nethermind, Besu (trace_call) and Parity use -32000; only Reth uses -32001. The ledger's "matches eth/debug getters" rationale is inaccurate: `eth_getBlockAccessList` returns null, and debug_trace fixtures use -32000.
  - -32001 is defensible only because -32000 collides with tx-validation errors in trace_call in all native clients. That needs maintainer sign-off, with the rationale corrected.
  - replayBlockTransactions of an unknown block is 2–2, with Reth test-locked to null, and has no fixture.
  - Anvil's ✅ on missing-block-filter is a false agreement: it trips the 300-block cap.
- **H09:** keep the core (error marks failure, REVERT keeps `{gasUsed, output}` for calls, halts omit or null, Parity labels, gas rules). Change three things:
  1. "Code size limit exceeded" → "Out of gas": Parity, OE, EIP-170 text, and upstream Geth and Besu Parity mappings.
  2. "Invalid code prefix 0xEF" → "Invalid code": the OpenEthereum label.
  3. Stop defining `revertReason` as decoded text; no implementer does this, and Besu uses raw bytes.
- The reverted-CREATE `{gasUsed, output}` shape has no native implementer, and its no-address justification collides with H23. Erigon, Nethermind and Reth all filter failed CREATEs by the would-be address. That needs a joint H09/H23 maintainer decision.
