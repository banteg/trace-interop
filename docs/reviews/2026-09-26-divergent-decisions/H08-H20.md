## Bottom line

**H08 (envelope): keep the recommendation unchanged.** No current native development build breaks the envelope.
- The only native deviation is Nethermind **2.0.0**, which drops `output` when only stateDiff is selected. 2.1.0-preview fixes it.
- Erigon's H08 "Differs" is misattributed. It comes from an output-bytes model check that fails because Erigon's `trace_call` environment reports GASLIMIT = 2^256−1, which is an H15 problem.
- The ledger's Erigon observation "unrequested trace is null" has no support in current evidence or source: Erigon initializes `Trace: []` on every path.
- Anvil is the only real outlier: it treats `[]` as `["trace"]`.

**H20 (vmTrace step semantics): keep almost everything, change two sub-rules, clarify one.**
- **Keep:**
  - MLOAD `mem`.
  - Post-op `used`.
  - Forwarded gas in CALL and CREATE `cost`, without the stipend.
  - `push` arity and order. All development builds now agree, and Besu's supposed reversed order is refuted by `probes-prague/vm-push-order`.
  - `store`, and all four `sub` rules.
  - Failed op present with `ex: null`.
  - No synthetic STOP, and pre-execution rejects omitted.
- **Change 1, CALL-family `mem` range:** accept either the full output window or exactly the copied prefix.
  - No cluster of three or more native clients shares either choice.
  - Both reconstruct memory exactly when `mem` is applied as a write.
  - No consumer I found depends on the difference.
  - Allowing both leaves only Nethermind needing a change (it emits nothing), plus Besu's already-open fabrication fix.
- **Change 2, `cost` of an op that halted exceptionally:** make it implementation-defined.
  - It depends on interpreter ordering. Parity charges before a static-write check; geth, Erigon and revm check first and report 0. On OOG, revm reports only the static part.
  - It has no accounting value, because a halted frame returns no gas.
- **Clarify, `cost` on a CALL or CREATE that fails its balance or depth precheck:** it still includes the forwarded gas, as in Parity, Erigon, Reth and the Geth draft.
  - Besu, and Nethermind for CREATE, report the net cost instead.
  - The draft's rationale claim that nested gas is "checkable without opcode knowledge" must be narrowed to ops that entered a frame.

**Scope question.** Specify exactly the parts that carry information and are already shared: pc and op presence, push, CALL/CREATE results, store, `mem` for writes and copies, post-op `used`, and CALL/CREATE `cost`.
- Consumers found in the wild use the structure and the replay fields. None depends on the range length or on the cost of a failed op.
- Specifying those two exactly would impose work on clients for no caller benefit.
- The low-value structural rules (implicit STOP, pre-execution rejects) can stay Parity's, because the fix is trivial and they meet the bar of two natives plus Parity.

### 2. Findings

1. **The "all four natives differ" headline is mostly already-fixed or single-client drift.** Per development build, what remains:
   - **Besu:** MCOPY; CALL `mem` fabrication; stipend in value-CALL cost; precompile cost; precheck cost and `sub`; bogus `ex` on halted ops.
   - **Erigon:** implicit STOP; `ex`+`store` kept on execution-error halts; undefined opcodes kept.
   - **Nethermind:** CALL `mem` missing; the 7400→9700 rewrite; halted ops deleted; precheck-CREATE cost.
   - **Reth:** MLOAD `mem`; CALL copied prefix; implicit STOP; precheck and precompile `sub`; undefined opcodes kept.

   No single draft rule is opposed by three or more natives, except the two changed below.

2. **CALL window: no shared behaviour exists.**
   - Full window: Parity plus Erigon (Bor copies Erigon).
   - Copied prefix: Besu, which falls out incidentally from its EVM's memory-update record (`VmTraceGenerator.java:159-165`), and revm-inspectors main.
   - The revm behaviour was introduced by our own #504 under the earlier "written bytes" draft (`mod.rs:569`, comment "CALL only overwrites the returned bytes"), so it is not independent native evidence.
   - Nethermind emits nothing.
   - Both choices reconstruct memory exactly when applied as a write; the ledger's rationale already says so. Whichever single choice is mandated, two clients must change.

3. **MLOAD is a real consensus.** Parity, Erigon, Nethermind, Besu, Bor and the Geth draft all emit it. Reth's null exists only because #504 followed the superseded narrowing (`mod.rs:882` "Only writes are tracked … MLOAD yield None"). A follow-up revm-inspectors PR is needed, and none is open.

4. **The cost of a halted op is ordering-dependent.**
   - For the same static SSTORE: Parity charges its SSTORE cost, geth/Erigon/revm report 0, and Besu reports all remaining gas.
   - For the same OOG MLOAD: Parity, Erigon and Geth report the full unpayable 35,184,775,266,310; revm reports 3.
   - No consumer uses it, and the child's leftover is 0 regardless. Requiring Parity's number would force revm to compute a dynamic cost it never charges.

5. **The precheck-failure cost is a spec gap, not a client split.**
   - The majority, including Parity, includes forwarded gas and returns it immediately.
   - The resulting `used` also includes a value call's 2300 stipend, which is EVM-correct: geth and Parity refund the stipend on a failed precheck.
   - So the relation used = prev − cost + child leftover does **not** hold for these ops. The harness already skips them (`vm_model.py`: gas relation only when `sub` is non-empty), but the ledger rationale overclaims.

6. **Nethermind 7400→9700 is a live bug in both builds.**
   - It is caught in `repeat/call-gas7400` ("cost: expected 7400, got 9700") but is absent from the H20 impact text and from `decisions/fixes.json`.
   - `a/call-gas7400`, the identical fixture, carries no H20 assertions, so its page shows NM 2.1.0-preview as ✅. That is a harness coverage inconsistency.

7. **Refuted:** `docs/source-review/vmtrace.md` C6 claimed "Besu multi-word push is top-first". `vm-push-order` shows Besu `DUP3 → [0x1,0x2,0x3,0x1]` and `SWAP2 → [0x1,0x3,0x2]`, both deepest-first.

8. **Consumers.** From GitHub code search via `gh search code` and local checkouts:
   - **Otterscan** (`src/execution/transaction/trace/traceInterpreter.ts`, RevertTrace) uses `pc`, `op`, `code` and the `sub` nesting. It zips `sub`s one-to-one with CALL/CREATE frames from `trace` and returns null on a count mismatch, so the `sub` placement rules matter to it. It does not use `mem`, `cost` or `used`.
   - **ApeWorX evm-trace** (`evm_trace/vmtrace.py`, `to_trace_frames`) replays `push` using Parity arity (DUPn pops n and pushes n+1), CALL's single result push, `mem` as a write, and `store`. Its 2026 hardening (evm-trace #84) now recomputes DUP/SWAP effects, memory expansion and MCOPY from bytecode. It raises on missing CALL/CREATE result pushes and tolerates the implicit STOP. Its stated equivalence covers pc, op, depth and stack only: "Memory/storage/gas are not included in that claim".
   - **cryo** `vm_traces` exports `pc, cost, used, op` by default, plus `push`, `mem` and `store`. It is the only consumer that surfaces `cost` and `used`, which argues for keeping CALL/CREATE `cost` and post-op `used` exact.
   - **flashboys2** (`gastoken.py`) requests only `["vmTrace"]` and reads `ex.store`. That is exactly what Nethermind 2.0.0 and Reth 0.43 broke.
   - **NilFoundation placeholder** (`load_block.py`) counts ops recursively, which is sensitive to the implicit STOP and to deleted failing ops.
   - Academic tools (InvCon, SmCon) dump raw vmTrace.
   - Typed clients (alloy, ethers-rs, rust-web3, web3.py types) define the shape only.
   - **Not consumers:** Blockscout has `vmTrace` only in test fixtures and cassettes; there are no hits in ethereum-etl or mev-inspect-py. Dune pipelines and indexers use call traces.
   - **New producers:** Polygon Bor (Jul 2026, Erigon-compatible) and Zilliqa zq2 show continuing demand.
   - Consumers never distinguish window from copied prefix, and never read the cost of a failed op.

### 4. Proposed replacement text

**Recommendation (ledger `H20.recommendation`).** Unchanged sentences are kept verbatim; changed parts are in bold.

> mem is the post-operation contents of the memory range the opcode's operands designate: MSTORE and MLOAD [off, off+32), MSTORE8 [off, off+1), and the destination of CALLDATACOPY, CODECOPY, EXTCODECOPY, RETURNDATACOPY and MCOPY. **For the CALL family the range starts at the output offset and is either the full output window [outOff, outOff+outSize) (preferred, as Parity) or exactly the bytes the call copied, [outOff, outOff+min(outSize, RETURNDATASIZE)); consumers may apply mem as a write under either, but must not infer RETURNDATASIZE from its length.** It is null when that range is empty or the opcode designates none (RETURN, REVERT, LOG*, KECCAK256, CREATE*). cost is the total gas deducted from the caller when the operation starts, including gas made available to a child frame (CALL family: the 63/64-capped forwarded gas, excluding the value stipend; CREATE family: all but 1/64)**, also when the call or creation fails its balance or depth precheck and that gas is returned at once**. ex.used is the caller's remaining gas after the operation, including unused child gas returned **(after a failed precheck: the forwarded gas and any value stipend)**. An operation that began executing and halted exceptionally is present with ex: null and sub: null**; its cost is an implementation-defined non-negative integer (the full cost it required, or the part charged before the halt) and has no accounting meaning, since a halted frame returns no gas**. Operations rejected before execution (undefined opcodes including the designated invalid 0xFE, stack underflow or overflow) are omitted, and there is no synthetic STOP, so every pc lies inside code. push is the top k stack words after execution, deepest first, where k is the number of words the opcode leaves in place of its inputs (DUPn and SWAPn n+1, CALL and CREATE 1 after the child returns). store is set only by SSTORE, from its key and value operands as quantities, whenever the SSTORE completes, even if the value is unchanged; TSTORE and SLOAD never set it. A selected vmTrace is always an object. An operation that entered a child frame, including precompile and empty-code targets, has that frame's trace as sub ({code: "0x", ops: []} if no instruction ran); operations that entered no frame (failed precheck, SELFDESTRUCT) have sub: null.

**Rationale (replacing `H20.rationale`):**

> Same-step effects let consumers follow execution without shifting writes between opcodes. Operand-derived ranges need no return-data dependency and match Parity, Erigon, Nethermind and Besu for MLOAD. For a CALL, the full window (Parity, Erigon) and the copied prefix (Besu, revm-inspectors) both reconstruct memory exactly when applied as writes, and no known consumer distinguishes them, so either is accepted. For an operation that entered a child frame, used = previous used − cost + child leftover (0 if the child halted) is checkable without opcode knowledge; a CALL or CREATE that fails its precheck instead gets its forwarded gas (and a value call's stipend) back directly. The cost of a halted operation depends on where an interpreter detects the fault, and nothing consumes it.

**Spec delta (`src/schemas/trace.yaml` `TraceVm.description`, and the matching `trace-profile.md` "VM `mem` is…" paragraph):**
- After "…including gas made available to a child frame: the 63/64-capped forwarded gas for the CALL family, excluding the value stipend, and all but 1/64 for the CREATE family", add: "; this also holds when the call or creation fails its balance or depth precheck and the gas is returned immediately".
- Replace "An operation that halted exceptionally keeps its pre-execution cost and has ex null and sub null." with "An operation that halted exceptionally has ex null and sub null; its cost is an implementation-defined non-negative integer."
- Replace "…MCOPY, and the full CALL-family output window." with "…MCOPY; for the CALL family, either the full output window (preferred) or exactly the bytes copied from return data, starting at the output offset."
- In `trace-profile.md`:
  - Drop "reverses an earlier draft that narrowed `mem` to written bytes" in favour of "the CALL-family range may be the full window or the copied prefix".
  - Add one sentence: "Consumers must not infer returned-data length from `mem`."

**Harness delta (for whoever implements it):**
- In `trace_interop/vm_model.py` `local_invariants`, accept `mem.data` length ∈ {outSize, min(outSize, returndata)}.
  - The returndata length can be read from the child's last RETURN/REVERT operands, or from the matching `trace` frame output.
  - A null `mem` is valid only when the chosen length is 0.
- Do not assert `cost` on ops with `ex: null`.
- Add H20 local invariants to `a/call-gas7400` (it currently carries only H08 and H21).
- Update the stale Geth "observed" string in `decisions/impact.json`.

### 2. Findings

- The envelope is effectively unanimous. The only native deviation is Nethermind 2.0.0 (release), fixed in 2.1.0-preview; #13667 is merged with uptake.
- **Erigon's H08 "Differs" is misattributed.**
  - `trace_interop/coverage.py:274` tags "Modelled execution returns exactly the independently computed bytes" as H08.
  - On `coverage/model-environment`, Erigon's output ends in `ffff…ff` because its `trace_call` environment reports GASLIMIT as 2^256−1 (Geth and NM give `0x5f5e100`). That is H15 (simulation block environment).
  - `model-environment-free` and `call-empty-types` errors ("fee cap less than block base fee") are also H15.
  - The `impact.json` Erigon observation "An unrequested `trace` component is `null`" is not reproduced anywhere in the 2026-09-26 matrix, and current source initializes the slice.
- Besu's "Partially assessed" comes from unsupported `trace_replayTransaction` (`-32601`) and internal errors on zero-fee or empty-type calls. None is an envelope defect.
- Consumers rely on the envelope being stable. For example, evm-trace's `RPCTraceResult` requires `vmTrace` to be present, and Otterscan reads `results.vmTrace`.
