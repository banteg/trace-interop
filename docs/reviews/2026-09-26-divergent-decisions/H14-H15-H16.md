# H14 (remaining), H15, H16: should the draft change?

2026-09-26 · read-only review · evidence: `evidence/2026-09-26/anvil` (reports.lock.json), draft `banteg/execution-apis@e437815d` (spec.lock.json) `src/trace/trace-profile.md` §"Simulation requests" / §"Execution results".

Build shorthand: native builds are Besu 26.9.0/26.9-develop (f9572aa8 source), Erigon 3.7.0/3.8.0-dev (e26d9bd4 source), Nethermind 2.0.0/2.1.0-preview (641592d2 source), Reth 2.5.2/2.6.0 (58a51b3e source). Anvil 1.8.3/nightly. Geth = our draft fork (not a vote). B = 765,625,000 wei (selected block base fee). "eth" = the same client's `eth_call` on the byte-identical call object (fee-compat corpus). All numbers below were re-decoded from the gzip observations directly from the evidence, not taken from report prose.

Caveat that applies to every Nethermind *release* trace_call cell: `trace_call` with the empty selection returns `-32603 Sequence contains no elements` (H08/H11 bug, fixed in the dev build), so Nethermind trace behavior is read from the dev build plus release `stateDiff` selections.

## Bottom line

| Decision | Verdict |
| --- | --- |
| **H15** | **Keep** all rules. Every native client's own `eth_call` already does what the draft asks: omitted fees → free, zero price → BASEFEE 0, positive price below base fee rejected, funding enforced, fees charged. The single exception is Reth, and Reth's `eth_call` is also the odd one among `eth_call`s. In Besu, Erigon and Nethermind the **trace path is the outlier inside the client**. Reth's trace path matches its own `eth_call` but is the only native client that charges nothing and checks no funding. That comes from a flag Reth added for OP operator fees. |
| **H16** | **Keep.** Replay and raw fee accounting is unanimous across all 11 builds (Erigon release raw was the exception, fixed by #24328, which is already in the dev build). Block-level effects are excluded everywhere. CallMany isolation holds everywhere except Besu (#11365). **Split** the item-error rule: "one error, no partial results" has cross-client support. `error.data.index` is invented, because only Erigon reports the index and only in message text. The index is cheap and justified by H14's no-text-matching rationale, so keep it but label it new. |
| **H14 remainder** | **Keep** -32602 for malformed input: every client does this for JSON-decoding failures, and Parity used InvalidParams. **Keep** the eth_simulateV1 codes -38012/-38013/-38014/-38025/-38026. All five codebases, including Besu, already contain that mapping in their `eth_simulateV1` path; the trace paths just don't call it. **Change** the fallback "any other validation failure is -32602". No client does this: simulate paths fall back to -32603, and it contradicts H14's own rationale for state-dependent failures. Proposed: -32602 for request-shape defects only, and -32003 (Transaction rejected, the H13 fallback) otherwise. **Clarify** which code wins when a request violates several rules. **Fix a ledger error**: "Besu has no -380xx codes" is false. |

### (2) Findings

- **The trace path is the outlier inside Besu, Erigon and Nethermind.** Each of these clients' `eth_call` already implements R1, R2, R6, R8 and R9 exactly as the draft states (fee-compat `*/eth` cells above).
  - **Besu:** `eth_call` picks relaxed params via `CallParameterUtil.isAllowExceedingBalance`. That predicate treats all-zero fees and unpriced blobs as zero-fee ([CallParameterUtil.java L60-81](https://github.com/besu-eth/besu/blob/f9572aa82a2dadb3dd1b218d3ca97101540faf97/ethereum/api/src/main/java/org/hyperledger/besu/ethereum/api/jsonrpc/internal/methods/CallParameterUtil.java#L60-L81)). The trace path hardcodes `TransactionValidationParams.transactionSimulator()` ([AbstractTraceByBlock.java L121-123](https://github.com/besu-eth/besu/blob/f9572aa82a2dadb3dd1b218d3ca97101540faf97/ethereum/api/src/main/java/org/hyperledger/besu/ethereum/api/jsonrpc/internal/methods/AbstractTraceByBlock.java#L121-L123)).
  - **Erigon:** `eth_call` and `debug_traceCall` run with `NoBaseFee`, `vm.ZeroUnpricedBaseFee` and `ZeroUnpricedBlobBaseFee` ([transactions/call.go L95-99](https://github.com/erigontech/erigon/blob/e26d9bd4056586e004488c31b561fb2663d46019/rpc/transactions/call.go#L95-L99); [execution/vm/evm.go L220-230](https://github.com/erigontech/erigon/blob/e26d9bd4056586e004488c31b561fb2663d46019/execution/vm/evm.go#L220-L230)). `trace_adhoc` has its own `ToMessage`, which backfills an all-zero fee with the base fee ([L188-211](https://github.com/erigontech/erigon/blob/e26d9bd4056586e004488c31b561fb2663d46019/rpc/jsonrpc/trace_adhoc.go#L188-L211)). It also forces GASLIMIT to max ([L1187-1188](https://github.com/erigontech/erigon/blob/e26d9bd4056586e004488c31b561fb2663d46019/rpc/jsonrpc/trace_adhoc.go#L1187-L1188)) and runs `gasBailout=true` ([L1226](https://github.com/erigontech/erigon/blob/e26d9bd4056586e004488c31b561fb2663d46019/rpc/jsonrpc/trace_adhoc.go#L1226)). The result skips the sender debit but still pays the tip, so a priced call mints the tip.
  - **Nethermind:** `eth_call`, `debug_traceCall` and the witness call all zero the header base fee when `!ShouldSetBaseFee()` ([EthRpcModule.TransactionExecutor.cs L68-70, L86](https://github.com/NethermindEth/nethermind/blob/641592d2b96fa1e2fa8e8a0b1761582a1728bd51/src/Nethermind/Nethermind.JsonRpc/Modules/Eth/EthRpcModule.TransactionExecutor.cs#L68-L86); DebugRpcModule.cs L124; WitnessCall.cs L72-74). `TraceRpcModule` never does.
  - These look **incidental**: separate code paths that were never aligned, not deliberate trace semantics.
- **Reth is consistent with itself but not with the other clients.**
  - Reth's shared call env sets `disable_base_fee` and `disable_fee_charge` ([call.rs L882-893](https://github.com/paradigmxyz/reth/blob/58a51b3ee3f6714ded9207b244a273c8afb592fd/crates/rpc/rpc-eth-api/src/helpers/call.rs#L882-L893)). In revm 43, `disable_fee_charge` skips the balance check, the upfront debit, the reimbursement and the beneficiary reward (revm-handler pre_execution.rs `calculate_caller_fee`; post_execution.rs `reimburse_caller`, `reward_beneficiary`).
  - The in-code comment gives the motive as "opstack operator fee charge" (issue #18470). The flag was added in #18634, reverted the same day (#18645), and re-added in #19073 (2025-10-16), so it is deliberate. The L1 consequence (no gas charge, no funding check) is not what the comment says it is for; **ask Reth whether that was intended.**
  - Reth accepts legacy below-base but rejects typed below-base. That comes from alloy-evm's fee normalizer (ledger H15 background) and is an incidental asymmetry.
- **Parity heritage** supports zero defaults (R1) and charging priced calls (R9). It contradicts funding enforcement (R8: the balance top-up) and GASLIMIT preservation (R10). Only Erigon's trace path still follows Parity on R10, and its own `eth_call` does not. On R8, every modern `eth_call` except Reth rejects underfunded priced calls, so the Parity top-up has no remaining constituency.
- **Anvil** matches the draft on R1, R3, R8 and R9. It differs on R2: it keeps BASEFEE B for zero-fee calls in both `eth_call` and `trace_call`, a deliberate dev-node choice with no base-fee zeroing. It also accepts below-base prices (R6).
- **debug_traceCall comparison** (source, not captured cross-client): Geth, Erigon and Nethermind `debug_traceCall` apply the same zero-fee BASEFEE rule and charge priced calls. Erigon's debug path uses `gasBailout=false` ([tracing.go L304-390](https://github.com/erigontech/erigon/blob/e26d9bd4056586e004488c31b561fb2663d46019/rpc/jsonrpc/tracing.go#L304-L390)), so a prestateTracer diff there shows the sender debit that Erigon's `trace_call` stateDiff omits. The draft therefore matches each client's other simulation paths, not only `eth_call`. No cross-client `debug_traceCall` fee capture exists yet; `evidence/2026-09-26/h29-debug-comparison` is Reth-only and not fee-related.

### (2) Findings

- **S1 is unanimous.** Sender, coinbase and burn deltas are byte-identical across all 11 builds on every replay and block-replay case checked, including the blob transfer (−60,375,000,131,079 sender, +42e12 coinbase, blob fee burned).
- **S2:** only Erigon 3.7.0 differs, fixed by merged #24328.
- **S5:** only Besu differs. Its `TraceCallMany` commits without a transaction boundary (#11365, open).
- **S7:** the "whole request fails" background claim in the ledger ("All four clients already fail the whole request on an item error") needs qualifying:
  - Besu returns a JSON-RPC error object nested inside a successful `result` (`{"result":{"jsonrpc":"2.0","id":1,"error":{-32603}}}`), which is an H25 envelope bug.
  - Nethermind dev streams item 0 and then truncates.
  - Only Erigon and Reth return one clean error. Reth does so only for typed below-base items; it accepts legacy ones, per H15.
- **S8 is invented**, and the draft should say so. Its only precedent is Erigon's `first run for txIndex N` message text, which shows that implementers found the index necessary.
  - eth_simulateV1 sidesteps the problem by returning per-call error objects inside results. Under the "one error, no partial results" rule, `error.data.index` is the minimal machine-readable equivalent.
  - The cost is trivial: every implementation already loops by index.

### (2) Findings

- **-32602 for malformed input is the de facto rule.** Every client emits it from its JSON decoder, and Parity used InvalidParams. The outliers are:
  - lenient decoders: Besu (negative count, scalar address), Nethermind (negative count, unknown mode or field), Erigon (unknown field);
  - Erigon and Nethermind returning -32000 for bad RLP, and Erigon for an unknown trace type;
  - Reth and Anvil returning null for integer paths.

  These are defects against a 3+-client cluster, not an alternative convention.
- **eth_simulateV1 codes: the implementer cost is small and the mapping already exists in every client.**
  - All five codebases, Besu included, contain an error-to-code mapping for -38012, -38013 and -38014. The trace paths bypass it and emit -32000, -32003 or -32603.
  - `eth_call` codes are not an alternative. They are unstandardized: Besu -32009/-32004, Reth and Anvil -32003, Erigon and Nethermind -32000 with free text. They would force text matching, which H14's rationale rules out.
  - **Correction:** ledger H14 background says "Besu has no -380xx codes". That is false at f9572aa8, which has `BlockStateCallError` with -38010, -38011, -38012, -38013, -38014, -38015, -38020, -38021, -38023 and -38026. Besu lacks only -38025.
- **Fallback "-32602 for any other validation failure" is invented and inconsistent with H14's rationale.**
  - No simulate implementation does it. Geth, Erigon, Nethermind and Besu fall back to -32603, and Reth to its generic codes.
  - Tip>cap is a request-shape defect (state-independent), so -32602 fits there. Geth and Erigon already use it, Anvil too.
  - The Geth draft's other -32602 fallbacks mix categories: a blob fee cap below the blob base fee is a state-dependent "valid request that cannot execute here", the direct analogue of -38012. Reporting it as "invalid params" contradicts "distinguish a malformed request from a valid request that cannot execute".
  - EIP-1474's -32003 "Transaction rejected" is the category the draft already uses as H13's generic fallback. Reth and Anvil already emit -32003 for unsigned rejections.
- **Multiple violations.** For tip-only positive, clients disagree on which violation to report: Geth, Erigon and Anvil say tip>cap; Besu and Nethermind say below base fee. The draft names only one. Geth's `preCheck` order (tip>cap before cap<base) is a reasonable tie-break: state-independent checks first.

### (3) Verdicts

| Sub-rule | Verdict |
| --- | --- |
| -32602 for malformed encodings, wrong types, unsupported shapes | **keep**; cluster = all clients + Parity. |
| -32602 for disagreeing `data`/`input` | **keep, contested.** Besu and Reth reject, and their `eth_call`s do too. Erigon dev, Nethermind and Anvil prefer `input` (as upstream Geth `eth_call` does). That is 2 v 2 among natives. Rejection is the safe choice; Erigon #24336 already implements it. Flag for maintainer input only if Nethermind objects in #13897 review. |
| -32602 for tip > cap | keep (Geth and Erigon simulate, Anvil). |
| -32602 for a non-null, unimplemented override | keep (unprobed; the alternative is silent mis-execution). |
| -38012 / -38013 / -38014 / -38025 / -38026 | **keep**; each client already has the mapping. |
| Fallback: any other validation failure → -32602 | **change (split)**; see below. |

### (4) Proposed replacement text

Ledger H14 recommendation, replacing the sentence "Report unsigned-call validation rejections with the eth_simulateV1 codes: … ; a validation failure without a listed code is -32602.":

> Report unsigned-call validation rejections with the eth_simulateV1 codes: -38012 base fee too low, -38013 intrinsic gas, -38014 insufficient funds, -38025 init-code size and -38026 client limit. A call object that is invalid regardless of state (a priority fee above the fee cap, a transaction type or field combination no transaction can carry, an empty authorization list) is -32602, and these checks take precedence when a request violates several rules. Any other rejection of a well-formed call at the selected block, such as a blob fee cap below the blob base fee or a type not active at that fork, is -32003 (Transaction rejected), the same fallback trace_rawTransaction uses.
