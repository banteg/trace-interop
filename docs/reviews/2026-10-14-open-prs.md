## 1. Executive Summary of Suboptimal Findings

### A. Code Bugs & Compile/Test Breakages Against Current `main`

1. **`besu-eth/besu#11360` — `FlatTraceGenerator.handlePrecompile` overwrites `"Precompile error"` with `"Reverted"` on altbn128 failures (`FlatTraceGenerator.java:308-312`):**
   - When Besu's `BN128_ADD` (`0x06`), `BN128_MUL` (`0x07`), or `BN128_PAIRING` (`0x08`) fails on invalid curve input, `AbstractAltBnPrecompiledContract` calls `frame.setRevertReason(Bytes.wrap("error".getBytes(UTF_8)))` (`0x6572726f72`) **and** returns `PrecompileContractResult.halt(ERROR, Optional.of(ExceptionalHaltReason.PRECOMPILE_ERROR))`.
   - `DebugOperationTracer.tracePrecompileCall` copies both `exceptionalHaltReason` and `revertReason` onto the caller's `CALL` `TraceFrame`.
   - In `#11360`, `handlePrecompile` first sets `.error(frame.getExceptionalHaltReason().map(ExceptionalHaltReason::getDescription))` (`"Precompile error"`), and immediately runs:
     ```java
     frame.getRevertReason().ifPresent(
         reason -> child.error(Optional.of("Reverted")).revertReason(reason.toHexString()));
     ```
   - This overwrites `child.error` from `"Precompile error"` to `"Reverted"` (with `result: null`, violating H09's invariant that `"Reverted"` frames have `result: {gasUsed, output}` and contradicting `#11347` where a root call to `0x06` reports `"error": "Precompile error"`).
   - `PrecompileFlatTraceTest.retainsOnlyNonzeroValuePrecompiles` (`line 169`) missed this because it only asserted `assertThat(child.getError()).isNotNull()` instead of `.isEqualTo("Precompile error")`.
   - **Fix:** Guard the `"Reverted"` error assignment with `if (frame.getExceptionalHaltReason().isEmpty())`.

2. **`besu-eth/besu#11435` — Hidden test failure against merged `#11432` (`trace_call_22_0_trace.json`):**
   - `#11432` (merged 2026-10-08) added `ethereum/api/src/test/resources/org/hyperledger/besu/ethereum/api/jsonrpc/trace/specs/trace-call/trace_call_22_0_trace.json`, a contract-creation `trace_call` fixture whose expected `"action"` omits `"creationMethod": "create"`.
   - When `#11435` (which adds `"creationMethod": "create"` to all `trace_call` creation actions) is rebased onto `main`, `TraceJsonRpcHttpBySpecTest` will fail on `trace_call_22_0_trace.json` unless that fixture is updated.

3. **`besu-eth/besu#10953` — Compile breakage against merged `#11379` (`AbstractTraceByHashTest.java:141`) & unaddressed `usmansaleem` review comments:**
   - `#11379` (merged 2026-10-13) changed `AbstractTraceByHash.resultByTransactionHash(Hash)` from returning `Stream<FlatTrace>` to `Optional<Stream<FlatTrace>>`. `#10953`'s new test `AbstractTraceByHashTest.java:141` calls `assertThat(traceByHash.resultByTransactionHash(transactionHash)).containsExactly(flatTrace)` and will fail to compile once merged with `main` (needs `.orElseThrow()`).
   - Reviewer `@usmansaleem` left an unresolved thread on `TraceFilter.java:200` pointing out that when `!traceBlockWithPipeline(...)` returns `false` (unavailable parent world state), `#10953` `break`s and returns a silently truncated `JsonRpcSuccessResponse` instead of `RpcErrorType.WORLD_STATE_UNAVAILABLE` (violating H06 and inconsistent with `#11407`'s `traceFilterByBlockHash`). `@usmansaleem` also requested a comment/test on `TraceServiceImpl` preserving raw pre-execution state for Linea's Lineth zkTracer.

4. **`besu-eth/besu#11395` — `rpcGasCap` checked before intrinsic/signature validation (`TransactionSimulator.java:322-331`) & unmapped validator reasons (`JsonRpcErrorConverter.java`):**
   - `TransactionSimulator.process(Transaction, ...)` checks `rpcGasCap > 0 && Long.compareUnsigned(transaction.getGasLimit(), rpcGasCap) > 0` *before* running `MainnetTransactionValidator.validate`. A malformed/bad-signature raw transaction that also has `gasLimit > rpcGasCap` returns `-32005` (`EXCEEDS_TRANSACTION_GAS_LIMIT`) instead of the state-independent format/signature error required by H13/H14 precedence rules.
   - `JsonRpcErrorConverter.convertTransactionInvalidReason` maps `EMPTY_CODE_DELEGATION`, but still leaves `INITCODE_TOO_LARGE`, `NONCE_OVERFLOW`, `UPFRONT_COST_EXCEEDS_UINT256`, and `INVALID_BLOB_COUNT` unmapped, falling through to `default -> RpcErrorType.INTERNAL_ERROR` (`-32603`).

5. **`erigontech/silkworm#2885` — Memory out-of-bounds read (`copy_memory`) and incomplete H20 coverage in `evm_trace.cpp`:**
   - `copy_memory_offset_len` only reads the low 64-bit limb (`stack[0][0]`, `stack[-2][0]`) of 256-bit `uint256` stack operands in `on_instruction_start`, and `copy_memory` (`evm_trace.cpp:575-589`) indexes `memory.data() + start + idx` with **no bounds check against `memory.size()`**, causing a heap buffer over-read when a `CALL`'s `outOff + outSize` exceeds actual expanded memory.
   - Silkworm's `VmTraceTracer` still has the remaining H20 bugs that Erigon fixed in `#24291` and `#24344`: synthetic trailing `STOP`, deleting a real single-instruction `STOP`, keeping halted `ex`/`store` on `EVMC_BAD_JUMP_DESTINATION` and `EVMC_WRITE_PROTECTION`, keeping pre-execution faults (`STACK_UNDERFLOW`, `STACK_OVERFLOW`, `UNDEFINED_INSTRUCTION`, `INVALID_INSTRUCTION`), and attaching an empty `sub` to `SELFDESTRUCT`.

6. **`ethereum/execution-apis#895` — Spec prose slightly behind 2026-10-12 H14/H15 update (`maxFeePerBlobGas` without `blobVersionedHashes`):**
   - `docs-api/docs/trace-profile.md:160`, `src/schemas/trace.yaml:98`, and `src/trace/methods.yaml:13` at head `29df74f9` (2026-10-11) still say *"A blob call carries `blobVersionedHashes` or `maxFeePerBlobGas`"*, whereas the 2026-10-12 H14/H15 update (`execution-apis#884`) settled that `maxFeePerBlobGas` without `blobVersionedHashes` is rejected at every fork.

7. **`ethereum/go-ethereum#35791` — Minor case-sensitivity asymmetry in `TraceFilter.UnmarshalJSON` (`eth/tracers/trace_types.go:200-227`):**
   - `TraceFilter.UnmarshalJSON` strips explicit `null` members using an exact-case `switch key`, then decodes into the struct with `encoding/json` (which matches field names case-insensitively). Thus `{"MODE": "union"}` is accepted, but `{"MODE": null}` is not stripped and fails in `TraceFilterMode.UnmarshalJSON` with `"mode must be a string"`. Using `strings.EqualFold` (or `strings.ToLower`) when stripping nulls makes case-insensitive filter member handling consistent.
