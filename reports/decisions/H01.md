# Method coverage

**Question:** Which trace_* methods must a client implement, and how does it signal the ones it does not?

H01 · Scope decision · [All decisions](../../decisions/README.md)

**Status: 🤝 Converged** · [Status definitions](../../decisions/README.md#status-key)

Converged on the full namespace: a client that serves `trace_*` implements all nine methods, with no optional subset or discovery mechanism. Erigon, Nethermind and Reth expose all nine, and so does the Geth draft fork; Besu lacks only individual replay, `trace_replayTransaction`, which Besu #11357 asks the team to reconsider. A method a client does not serve still returns -32601, never an empty result. This records direction from implementations, not unanimous formal approval.

Policy evidence: [Besu #11357: reconsider trace_replayTransaction](https://github.com/besu-eth/besu/issues/11357).

[Client positions](../../decisions/README.md#client-positions): none recorded.

## Recommendation

A client that serves the trace namespace implements all nine methods; there is no optional subset or discovery mechanism. A method the client does not serve returns -32601, never a fabricated empty result, so an unsupported operation stays distinguishable from a valid query with no trace. Besu adds individual replay, trace_replayTransaction.

A caller should be able to distinguish an unsupported operation from a valid query with no trace.

## Background

The [Parity RPC trait at 55c90d4](https://github.com/openethereum/parity-ethereum/blob/55c90d4016505317034e3e98f699af07f5404b63/rpc/src/v1/traits/traces.rs#L28-L70) exposes nine distinct methods. They did not arrive as one indivisible feature: [multi-call was added in 2017](https://github.com/openethereum/parity-ethereum/commit/f157461ee19740c8d013bb9885d3aa0aa5f91a8a) and [block replay in 2018](https://github.com/openethereum/parity-ethereum/commit/df5d27d5163e8d6f6d00f4f8996ce384fcf804cf). The [OpenEthereum trace guide](https://openethereum.github.io/JSONRPC-trace-module) also distinguishes ad hoc execution from indexed historical filtering, which requires tracing to have been enabled. This history supports specifying method contracts separately; it does not establish that every modern client must implement every method.

The [2026 standardization issue](https://github.com/ethereum/execution-apis/issues/890) records that Erigon, Reth and Nethermind expose the nine-method namespace, while Besu lacks individual replay and Geth has a different debug tracing API. The [draft PR](https://github.com/ethereum/execution-apis/pull/895) leaves method scope and support policy for review. An unimplemented method must remain distinguishable from an implemented lookup that found no records; whether the profile is optional or split between execution and historical search is still a policy decision, not client agreement.

[Besu #6597](https://github.com/besu-eth/besu/issues/6597) requested `trace_replayTransaction` for Blockscout. A Besu contributor said the core team did not plan to implement it because it is outside the Ethereum specification and suggested `debug_traceTransaction`; another user noted that exposing the `DEBUG` namespace on a public endpoint was undesirable. The issue was closed due to age in March 2025, without an implementing PR. This records the team's stated scope at that time, not a current agreement on this profile.

[Besu #11357](https://github.com/besu-eth/besu/issues/11357), opened 2026-09-23, asks the team to reconsider individual replay using this project's cross-client H01 evidence, or to state that core support remains out of scope. [Besu #9699](https://github.com/besu-eth/besu/issues/9699) separately tracks pre-execution state changes that transaction replay must account for. Neither issue changes the behavior observed in the pinned builds.

### All nine methods (2026-09-26)

The draft now requires the full namespace. Erigon, Nethermind and Reth already expose all nine methods, and the Geth draft fork implements them; the only gap is Besu's individual replay. An optional subset would push every caller into probing for support and make "the trace API" mean something different per client, while the historical order in which Parity added the methods does not make any of them optional today. Individual replay is also the cheapest method to provide once block replay exists, since it traces one transaction of an already replayable block.
