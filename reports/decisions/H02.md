# trace_get selector and return shape

**Question:** What does trace_get's path argument select, and does it return one trace or a list?

H02 · Spec decision · [All decisions](../../decisions/README.md)

**Status: 🤝 Converged** · [Status definitions](../../decisions/README.md#status-key)

## Recommendation

Treat the argument as one traceAddress path: [] is root, ["0x0"] first child, ["0x6","0x0"] a nested child. Return one trace object or null for a missing transaction/path. Keep output traceAddress entries as JSON integers; callers convert them to minimal hex quantities for trace_get input. Integer request entries return -32602.

The lookup argument should identify the same path that traceAddress describes, with a singular result matching the method name.

## Background

Parity modeled `trace_get` as a [single `Vec<Index>` path returning an optional object](https://github.com/openethereum/parity-ethereum/blob/55c90d4016505317034e3e98f699af07f5404b63/rpc/src/v1/impls/traces.rs#L84-L93). Its [trace database compares the full path](https://github.com/openethereum/parity-ethereum/blob/55c90d4016505317034e3e98f699af07f5404b63/ethcore/trace/src/db.rs#L267-L286), so an empty path identifies the root rather than a flat position. Parity [fixed `traceAddress` handling in 2016](https://github.com/openethereum/parity-ethereum/commit/948b614f4072d89678810c34b5ae23a1eb7bdf00). Its [Index deserializer](https://github.com/openethereum/parity-ethereum/blob/55c90d4016505317034e3e98f699af07f5404b63/rpc/src/v1/types/index.rs#L23-L64) accepted hex and decimal strings, but not JSON number tokens.

The pinned [Erigon lookup](https://github.com/erigontech/erigon/blob/c25b8e47dc1a77ecdbd15d38ba3beae1d29530ec/rpc/jsonrpc/trace_filtering.go#L134-L149) also compares the whole path; [Reth](https://github.com/paradigmxyz/reth/blob/03cb186c1d36eebbacc7bda08f36e25711d0804e/crates/rpc/rpc/src/trace.rs#L220-L242) uses the first supplied index as a flat position; [Nethermind](https://github.com/NethermindEth/nethermind/blob/a404c4f06a67aee52cc448216b8d37a77062f106/src/Nethermind/Nethermind.JsonRpc/Modules/Trace/TraceRpcModule.cs#L402-L424) returns a collection. The path and singular-result proposal follows Parity, but changing either client needs compatibility review.

Parity's [localized-trace serializer](https://github.com/openethereum/parity-ethereum/blob/55c90d4016505317034e3e98f699af07f5404b63/rpc/src/v1/types/trace.rs#L501-L535) writes `traceAddress` from `Vec<usize>` as JSON integers. The draft retains that output representation and uses hex quantities for request indices. The conversion belongs at the caller boundary, not in trace responses. Requiring minimal hex input deliberately narrows Parity's acceptance of decimal strings; tree-path meaning does not depend on the two directions having identical wire types.

Reth has since converged upstream: [#27366](https://github.com/paradigmxyz/reth/pull/27366) selects `trace_get` results by tree path, and main at [861a5616](https://github.com/paradigmxyz/reth/blob/861a56167cd4eee8ed66e2bfb5d54a6b0620b40d/crates/rpc/rpc/src/trace.rs#L220-L242) compares the full path, keeping flat-position lookup only as an internal helper. Released 2.6.0 still uses the flat selector.
