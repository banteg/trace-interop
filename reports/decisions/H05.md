# Post-merge reward records

H05 · Spec decision · [All decisions](../../decisions/README.md)

**Status: ⚪ Under review** · [Status definitions](../../decisions/README.md#status-key)

No policy conclusion has been recorded. Implementation observations below do not establish client-team agreement.

## Recommendation

Do not emit a synthetic PoW block reward on a PoS block. Represent real protocol balance changes only under explicitly defined semantics; keep transaction tips in transaction accounting. Define nullable localization fields separately for non-transaction records.

A reward trace should correspond to a real protocol operation, not a zero-value placeholder that changes pagination.

## Background

Parity [added reward traces in 2017](https://github.com/openethereum/parity-ethereum/commit/06862c7dee400e3b9f37c6cfdae52c081ee9d7f1) for consensus payouts and then [made transaction IDs optional](https://github.com/openethereum/parity-ethereum/commit/1f3f91136ca9438336e5eb824ce31555ac116fae) because a reward is not a transaction. Its [serializer test](https://github.com/openethereum/parity-ethereum/blob/55c90d4016505317034e3e98f699af07f5404b63/rpc/src/v1/types/trace.rs#L814-L831) expects a `reward` action with null transaction localization. This explains why the trace model has non-transaction records at all.

[EIP-3675](https://eips.ethereum.org/EIPS/eip-3675#block-and-ommer-rewards) removed the PoW block and ommer balance increases at the Merge while leaving transaction fees in place. [EIP-4895](https://eips.ethereum.org/EIPS/eip-4895) later introduced withdrawals as block-level balance changes, but neither Parity's reward encoding nor that EIP defines a `trace_*` withdrawal action. The observed Besu and Nethermind zero-value reward placeholders therefore should not be treated as actual post-Merge rewards; whether to include withdrawals or other system changes needs an explicit separate trace contract.
