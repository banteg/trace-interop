# Replay transactionHash field

H07 · Spec decision · [All decisions](../README.md#decisions-to-review)

**Status: ⚪ Under review** · [Status definitions](../../decisions/README.md#status-key)

No policy conclusion has been recorded. Implementation observations below do not establish client-team agreement.

## Recommendation

Include transactionHash in both individual and per-transaction block-replay envelopes. Do not require it for unsigned trace_call or trace_callMany simulations.

A replay object should keep its identity when stored or moved out of its original request context.

## Background

[Parity issue #8725](https://github.com/openethereum/parity-ethereum/issues/8725) reported that `trace_replayBlockTransactions` returned per-transaction state diffs without hashes, forcing callers to pair array positions with block transactions. [The 2018 fix](https://github.com/openethereum/parity-ethereum/commit/526c61e2c053f7ef98be93b118120ab585f4aaad) added a distinct `TraceResultsWithTransactionHash` type for block replay. The [Parity RPC trait](https://github.com/openethereum/parity-ethereum/blob/55c90d4016505317034e3e98f699af07f5404b63/rpc/src/v1/traits/traces.rs#L59-L70) and [response structs](https://github.com/openethereum/parity-ethereum/blob/55c90d4016505317034e3e98f699af07f5404b63/rpc/src/v1/types/trace.rs#L625-L671) retained a plain `TraceResults` for individual replay, whose request already supplies the hash.

The [OpenEthereum examples](https://openethereum.github.io/JSONRPC-trace-module) include `transactionHash` in block-replay items but omit it in individual replay, as does the pinned [Reth implementation](https://github.com/paradigmxyz/reth/blob/03cb186c1d36eebbacc7bda08f36e25711d0804e/crates/rpc/rpc/src/trace.rs). Requiring it in both is an intentional additive contract improvement: each replay result remains identifiable when cached, forwarded or detached from the request. The benefit is consistent self-contained envelopes, not restoration of the original individual-replay shape. Clients and strict decoders need compatibility review.

Supporting controls (not standalone assertions): [initial/replay-missing](../cases/initial/replay-missing.md).
