# Failed frame results and error labels

H09 · Spec decision · [All decisions](../../decisions/README.md)

**Status: ⚪ Under review** · [Status definitions](../../decisions/README.md#status-key)

No policy conclusion has been recorded. Implementation observations below do not establish client-team agreement.

## Recommendation

The error field alone determines failure. A REVERT frame has error "Reverted" and requires result {gasUsed, output} with that frame’s gas and revert bytes, for CREATE too and never with address or code. An exceptional halt may omit result or set it to null; it consumes the frame’s action.gas. Use Parity’s failure labels: "Reverted", "Out of gas", "Bad instruction", "Bad jump destination", "Stack underflow", "Out of stack", "Mutable Call In Static Context", "Built-in failed" and "Out of bounds", plus "Contract address collision", "Code size limit exceeded", "Invalid code prefix 0xEF" and "Nonce overflow" for post-Parity failures. Any other string is an extension that consumers treat as a generic failure. revertReason, if present, is the decoded Error(string) text; raw revert bytes live in result.output. Frame gas follows Parity: root action.gas is the transaction gas minus intrinsic gas (including access-list and authorization costs); root result.gasUsed is execution gas before refunds, excluding intrinsic gas and the EIP-7623 floor; nested CALL-family action.gas is the gas forwarded after the 63/64 cap plus the 2300 stipend for a value transfer; CREATE gasUsed includes the code deposit.

Consumers need the raw revert data and failure identity without parsing implementation-specific English or mistaking a failure for success. Only a REVERT carries data that error cannot; a null result on a halt adds nothing.

## Background

Parity [added explicit trace errors in 2016](https://github.com/openethereum/parity-ethereum/commit/da2c2e5fc67010dbd6e6300d856b0dfa06f0b569). Its [failure enum](https://github.com/openethereum/parity-ethereum/blob/55c90d4016505317034e3e98f699af07f5404b63/ethcore/trace/src/types/error.rs#L24-L95) maps VM failures to stable labels including Reverted and Out of gas; its [trace serializer](https://github.com/openethereum/parity-ethereum/blob/55c90d4016505317034e3e98f699af07f5404b63/rpc/src/v1/types/trace.rs#L501-L536) emits an `error` field on failure and omits `result`. Parity's [failure serialization test](https://github.com/openethereum/parity-ethereum/blob/55c90d4016505317034e3e98f699af07f5404b63/rpc/src/v1/types/trace.rs#L722-L743) locks this shape. The pinned [Nethermind writer](https://github.com/NethermindEth/nethermind/blob/a404c4f06a67aee52cc448216b8d37a77062f106/src/Nethermind/Nethermind.JsonRpc/Modules/Trace/ParityReplayEnvelopeWriter.cs#L94-L105) follows the same error-versus-result branch.

[EIP-140](https://eips.ethereum.org/EIPS/eip-140#specification) requires REVERT to retain returndata and unused gas for the caller, unlike an exceptional out-of-gas halt. That execution fact motivates preserving observed revert bytes and measured gas where a trace format can express them, but it does not itself define a failed-frame JSON `result`. The Besu and Nethermind cases should be separated into missing failure status, missing execution data, and wire-shape choices.

A failed-frame `result` is not new. Erigon and Reth have long emitted `result` on failed frames: `{gasUsed, output}` on a REVERT CALL and `result: null` on other failures ([Erigon trace_adhoc.go](https://github.com/erigontech/erigon/blob/3b4861d10387ca3e19f7b16d1b8c0ec1fcd616cd/rpc/jsonrpc/trace_adhoc.go#L517-L529); revm-inspectors [types.rs](https://github.com/paradigmxyz/revm-inspectors/blob/aac35449a4cacfe4c71477211a383c719acbf904/src/tracing/types.rs)), and Alloy and TrueBlocks decode both shapes. The new part is the failed-CREATE shape. Erigon and Reth report a reverted CREATE as `{address, code, gasUsed}` with the would-be address and the revert bytes under `code`; Alloy’s `TraceFilterMatcher` then matches that address against `toAddress`, where no contract exists. Besu and Nethermind emit `error` only. The envelope output cannot replace nested-frame revert bytes.

### Revised recommendation (2026-09-24 source review)

The previous recommendation required an explicit `result` on every failed frame, null when no data applied, and left the failure vocabulary undefined. Requiring null for an exceptional halt added nothing to `error` and forced Besu and Nethermind to change for no consumer benefit, so a halt may now omit `result`. The REVERT result stays required: Besu and Nethermind must add it, and Erigon and Reth must report a reverted CREATE as `{gasUsed, output}` without the would-be address. The labels are Parity’s ([error.rs](https://github.com/openethereum/parity-ethereum/blob/55c90d4016505317034e3e98f699af07f5404b63/ethcore/trace/src/types/error.rs#L24-L95)) plus four post-Parity kinds. Only "Reverted" is universal today, so every client changes some labels: a static-context write is "Illegal state change" in Besu, "out of gas: write protection" in Erigon and the Geth draft, "Static call violation" in Nethermind and `StateChangeDuringStaticCall` in Reth; Erigon and the Geth draft lower-case "out of gas" and leak library text for precompile failures; Reth falls back to Rust `Debug` names such as `NotActivated`; Nethermind reports unknown failures as "Error" and precompile failures as "Out of gas". `revertReason` is emitted only by Besu, with raw bytes rather than decoded text. The frame gas rules were previously unwritten; every client already agrees with Parity on every frame in the matrix except Besu’s callMany frames (H16) and its degenerate `gasUsed` on raw and cross-fork filter paths. See [call-trace A1–A3 and A6](../../docs/source-review/call-trace.md).
