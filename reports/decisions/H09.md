# Failed frame results and error labels

**Question:** How does a failed frame report its failure: which `result` fields remain, and which `error` labels are allowed?

H09 · Spec decision · [All decisions](../../decisions/README.md)

**Status: 🤝 Converged** · [Status definitions](../../decisions/README.md#status-key)

Converged on the failed-frame format, including a reverted CREATE reporting {gasUsed, output} with error "Reverted" and no address or code, as a reverted CALL does. Erigon proposed the same shape on execution-apis#890 after the heads-up, the Erigon and Nethermind development builds implement it (#24355, #24356; #13981), and a fix PR implements it for Reth (revm-inspectors). Parity’s failure labels, with the listed extensions, are part of the same fixes. This records direction from implementations and client teams, not unanimous formal approval.

## Recommendation

The error field alone determines failure. A REVERT frame has error "Reverted" and requires result {gasUsed, output} with that frame’s gas and revert bytes, for CREATE too and never with address or code. An exceptional halt may omit result or set it to null; it consumes the frame’s action.gas. Use Parity’s failure labels: "Reverted", "Out of gas", "Bad instruction", "Bad jump destination", "Stack underflow", "Out of stack", "Mutable Call In Static Context", "Built-in failed" and "Out of bounds". As in Parity and OpenEthereum, a code-deposit failure, including code above the EIP-170 size limit, is "Out of gas", and returned code starting with 0xEF (EIP-3541) is "Invalid code". Beyond Parity, which reported an address collision as "Out of gas" and emitted no frame for failed prechecks, use "Contract address collision", "Nonce overflow", "Insufficient balance for transfer" and "Max call depth exceeded". Any other string is an extension that consumers treat as a generic failure. revertReason is not part of this format; raw revert bytes live in result.output, and a client that emits revertReason must also emit result. Frame gas follows Parity: root action.gas is the transaction gas minus intrinsic gas (including access-list and authorization costs); root result.gasUsed is execution gas before refunds, excluding intrinsic gas and the EIP-7623 floor; nested CALL-family action.gas is the gas forwarded after the 63/64 cap plus the 2300 stipend for a value transfer; CREATE gasUsed includes the code deposit.

Consumers need the raw revert data and failure identity without parsing implementation-specific English or mistaking a failure for success. Only a REVERT carries data that error cannot; a null result on a halt adds nothing. A reverted CREATE reports no address or code because no contract exists at the address it would have occupied; H23 matches a record only on addresses it reports, so this shape and that filter rule stand together.

## Background

Parity [added explicit trace errors in 2016](https://github.com/openethereum/parity-ethereum/commit/da2c2e5fc67010dbd6e6300d856b0dfa06f0b569). Its [failure enum](https://github.com/openethereum/parity-ethereum/blob/55c90d4016505317034e3e98f699af07f5404b63/ethcore/trace/src/types/error.rs#L24-L95) maps VM failures to stable labels including Reverted and Out of gas; its [trace serializer](https://github.com/openethereum/parity-ethereum/blob/55c90d4016505317034e3e98f699af07f5404b63/rpc/src/v1/types/trace.rs#L501-L536) emits an `error` field on failure and omits `result`. Parity's [failure serialization test](https://github.com/openethereum/parity-ethereum/blob/55c90d4016505317034e3e98f699af07f5404b63/rpc/src/v1/types/trace.rs#L722-L743) locks this shape. The pinned [Nethermind writer](https://github.com/NethermindEth/nethermind/blob/a404c4f06a67aee52cc448216b8d37a77062f106/src/Nethermind/Nethermind.JsonRpc/Modules/Trace/ParityReplayEnvelopeWriter.cs#L94-L105) follows the same error-versus-result branch.

[EIP-140](https://eips.ethereum.org/EIPS/eip-140#specification) requires REVERT to retain returndata and unused gas for the caller, unlike an exceptional out-of-gas halt. That execution fact motivates preserving observed revert bytes and measured gas where a trace format can express them, but it does not itself define a failed-frame JSON `result`. The Besu and Nethermind cases should be separated into missing failure status, missing execution data, and wire-shape choices.

A failed-frame `result` is not new. Erigon and Reth have long emitted `result` on failed frames: `{gasUsed, output}` on a REVERT CALL and `result: null` on other failures ([Erigon trace_adhoc.go](https://github.com/erigontech/erigon/blob/3b4861d10387ca3e19f7b16d1b8c0ec1fcd616cd/rpc/jsonrpc/trace_adhoc.go#L517-L529); revm-inspectors [types.rs](https://github.com/paradigmxyz/revm-inspectors/blob/aac35449a4cacfe4c71477211a383c719acbf904/src/tracing/types.rs)), and Alloy and TrueBlocks decode both shapes. The new part is the failed-CREATE shape. Erigon and Reth report a reverted CREATE as `{address, code, gasUsed}` with the would-be address and the revert bytes under `code`; Alloy’s `TraceFilterMatcher` then matches that address against `toAddress`, where no contract exists. Besu and Nethermind emit `error` only. The envelope output cannot replace nested-frame revert bytes.

### Revised recommendation (2026-09-24 source review)

The previous recommendation required an explicit `result` on every failed frame, null when no data applied, and left the failure vocabulary undefined. Requiring null for an exceptional halt added nothing to `error` and forced Besu and Nethermind to change for no consumer benefit, so a halt may now omit `result`. The REVERT result stays required: Besu and Nethermind must add it, and Erigon and Reth must report a reverted CREATE as `{gasUsed, output}` without the would-be address. The labels are Parity’s ([error.rs](https://github.com/openethereum/parity-ethereum/blob/55c90d4016505317034e3e98f699af07f5404b63/ethcore/trace/src/types/error.rs#L24-L95)) plus four kinds Parity did not distinguish. Only "Reverted" is universal today, so every client changes some labels: a static-context write is "Illegal state change" in Besu, "out of gas: write protection" in Erigon and the Geth draft, "Static call violation" in Nethermind and `StateChangeDuringStaticCall` in Reth; Erigon and the Geth draft lower-case "out of gas" and leak library text for precompile failures; Reth falls back to Rust `Debug` names such as `NotActivated`; Nethermind reports unknown failures as "Error" and precompile failures as "Out of gas". `revertReason` is emitted only by Besu, with raw bytes rather than decoded text. The frame gas rules were previously unwritten; every client already agrees with Parity on every frame in the matrix except Besu’s callMany frames (H16) and its degenerate `gasUsed` on raw and cross-fork filter paths. See [call-trace A1–A3 and A6](../../docs/source-review/call-trace.md).

### Settled details (2026-09-24, Geth implementation)

EIP-3860 defines an oversized CREATE initcode as an exceptional abort of the creating frame, treated like running out of gas, so that frame fails with "Out of gas" and no new label is needed. The designated invalid instruction 0xFE is an undefined opcode in Parity’s instruction table; its frame fails with "Bad instruction" (H20 omits the opcode from vmTrace).

### Divergent-decisions review (2026-09-26)

The [review](../../docs/reviews/2026-09-26-divergent-decisions/H06-H09.md) kept the core of this decision and changed two labels. Parity and OpenEthereum reported a code-deposit failure, including code above the EIP-170 limit, as "Out of gas", which is EIP-170’s own wording and what the Parity-format flatCallTracers of upstream Geth and Besu emit; OpenEthereum labelled the EIP-3541 0xEF prefix "Invalid code". No client emitted the draft’s "Code size limit exceeded" or "Invalid code prefix 0xEF", so both now follow the Parity lineage, as the EIP-3860 initcode rule already did. Parity also reported an address collision as "Out of gas"; "Contract address collision", which Erigon and Geth spell the same way, is kept as a deliberate refinement. No trace_* client emits decoded revertReason text: Besu, the only emitter, writes the raw revert bytes on the root frame, consistent with its receipts, so revertReason is no longer defined. The reverted-CREATE result {gasUsed, output} has no native implementer: Erigon, Reth and Anvil emit {address, code, gasUsed} with the would-be address as a side effect of reusing the success serializer, and Besu and Nethermind emit no result. It is kept because no contract exists at that address, and H23 now states the matching rule that depends on it; adopting the client shape would reverse both decisions.

### EIP-8141 frame transactions (2026-09-27)

[execution-apis#909](https://github.com/ethereum/execution-apis/pull/909) (Nethermind, provisional) renders each frame of an EIP-8141 frame transaction as a child of one synthetic root call from the sender to `ENTRY_POINT`. A reverting frame has error "Reverted"; the [review comment](https://github.com/ethereum/execution-apis/pull/909#issuecomment-5856338610) asks it to keep `result: {gasUsed, output}` with the revert bytes and to define the root's `error` in `trace_*` as `callTracer` does (present if and only if the receipt status is 0). Its "frame skipped" label is an extension until EIP-8141 is scheduled. No captured chain has frame transactions, so this is untested until a second client implements them.

## Decision needed

Add discriminating fixtures: a static-context write, a precompile failure and an opcode not yet active, and compare labels exactly for those failure kinds. The mined-probes chain already pins the exact Reverted label and {gasUsed, output} result of mined top-level and nested reverted CREATEs, root gasUsed before an SSTORE refund, and root action.gas against the modelled intrinsic gas. `probes-prague` covers the EIP-170 code size limit, a failed code deposit and the EIP-3541 0xEF prefix. Every client keeps the failed frame without a result, but only the Geth draft and the Erigon (#24356) and Nethermind (#13981) development builds use both labels: Nethermind 2.0.0 reports "Out of gas" for the size limit and "Error" for the prefix, Besu "Code is too large" and "Code is invalid", Erigon 3.7.0 Go error text for all three, and Reth and Anvil the revm names `CreateContractSizeLimit` and `CreateContractStartingWithEF`.
