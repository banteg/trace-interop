## Recommendation

Validate trace_rawTransaction for execution against the selected state and fork: signature, chain identity, nonce equality (both low and high), balance for value and upfront gas, intrinsic gas, fees and sender-code restrictions with the EIP-7702 delegation exception. Do not change signed fields, override the sender nonce or supplement its balance. This is not pool admission: exclude local replacement, already-known and minimum-tip policies. Propose -32003 (Transaction rejected) for a decodable transaction that fails validation; malformed encoding or parameters use -32602. Valid execution that REVERTs or halts still returns a trace.

A signed trace should describe those bytes executing against the selected state. Skipping nonce validation can change CREATE addresses and nonce-dependent behavior; overriding nonce or balance instead invents a different pre-state. Strict validation intentionally tightens historical permissive simulation and can reject queued or already-mined transactions at latest state. Client acceptance alone does not establish a deliberate nonce policy, and malformed error JSON does not prove validation was skipped.

## Background

The [published gist](https://gist.github.com/banteg/d32a87ed2c47dfa4dbf1958235f8bf82/47fd6ec6f9b7644be94545f69383e595c8b5d391#h13), last revised on 2026-09-14 at 22:11:56 UTC, recommended strict nonce/validity checks. Our draft temporarily switched to relaxed nonce simulation in execution-apis [a636383a](https://github.com/banteg/execution-apis/commit/a636383af0c99f5ce6304ad6d6342deb23e294c2), committed 2026-09-22 at 20:36:58 UTC, and trace-interop [922c12f](https://github.com/banteg/trace-interop/commit/922c12f284617917f051fc4c10f12feaab2ec3f9), committed at 20:38:08 UTC.

[Erigon’s comment](https://github.com/ethereum/execution-apis/issues/890#issuecomment-5784143408) was created and last updated at 21:05:09 UTC on September 22. Despite following those commits chronologically, its content explicitly supports strict validation and asks to include balance and EIP-3607. The unchanged gist is a plausible source for its agreement, but we cannot establish which revision the author read. Restoring strict validation aligns our recommendation with that stated position; it is not evidence that Erigon changed its mind or endorsed relaxed simulation.

The earlier transfer has signed nonce 0x86 against state nonce 0x85. Erigon and Nethermind report a state nonce transition 0x85 → 0x86. That demonstrates incrementing the selected account nonce, not literal mutation of signed bytes, and by itself does not identify the CREATE address. The new CREATE constructor returns ADDRESS so the execution context can be observed directly.

The archived initial/raw-valid-default-block name is misleading: it contains signed nonce 0 at state nonce 133 and is a low-nonce negative control. It remains unchanged as historical evidence. The new corpus explicitly names high and low mismatches, uses matched funded controls, and includes EIP-3607 rejection alongside a permitted EIP-7702 sender.

Erigon reports that OpenEthereum skipped nonce checks and could supplement sender balance. Strictness is therefore an intentional compatibility change, not restoration of the legacy contract. Future-nonce queueing in eth_sendRawTransaction is not a reason to skip execution validity: a pool can retain a transaction that cannot execute next against the selected state. Selecting its mined block also does not generally select its pre-transaction state, because block-state selectors conventionally refer to post-state.

The fresh raw-validation corpus uses independently verified Prague state and observable storage/output markers. Besu executes wrong-chain and ordinary-code-sender probes, but returns empty success-shaped traces for nonce, funds, intrinsic-gas and base-fee failures. Erigon executes nonce, funds and ordinary-code-sender probes; Nethermind executes nonce and ordinary-code-sender probes but emits malformed JSON for the other invalid inputs. Reth rejects every invalid probe. Erigon and Nethermind CREATE output, returned address and stateDiff identify the state-nonce address for both low and high signed nonces. See the [H13 validation study](../../docs/h13-validation.md) for bounded conclusions and reproduction.

## Decision needed

Confirm strict execution validation and the proposed -32003 mapping with client teams. Preserve permissive simulation only through separately specified facilities. Use the raw-validation corpus to distinguish RPC rejection, malformed serialization, result-shaped failures and actual EVM effects, with valid controls under every trace selection. H12 historical selection remains separate: replay a mined transaction with trace_replayTransaction to obtain its actual pre-transaction state.
