# Unsigned simulation fees and block environment

H15 · Spec decision / likely environment bug · [All decisions](../README.md#decisions-to-review)

**Status: ⚪ Under review** · [Status definitions](../../decisions/README.md#status-key)

No policy conclusion has been recorded. Implementation observations below do not establish client-team agreement.

## Recommendation

Allow explicit zero-fee unsigned simulations (legacy gasPrice zero or an all-zero EIP-1559 execution-fee pair) without changing the selected block’s BASEFEE or other block fields. For priced simulations, require the legacy price or EIP-1559 fee cap to cover the block base fee, and require the priority-fee cap not to exceed the total fee cap. Enforce the applicable transaction funding requirements, expose the effective gas price through GASPRICE, and simulate upfront gas payment, refunds, base-fee burn and beneficiary tips. These effects must influence execution and later calls regardless of which trace components are requested. Apply the same policy to trace_call and trace_callMany; keep strict signed validation separate.

Relaxing transaction admission for a hypothetical call should not silently rewrite the block the caller selected.

## Background

Parity's [call-request adapter](https://github.com/openethereum/parity-ethereum/blob/55c90d4016505317034e3e98f699af07f5404b63/rpc/src/v1/helpers/fake_sign.rs#L24-L37) defaulted an unsigned call's `gasPrice` to zero and fake-signed it for the same [virtual execution path](https://github.com/openethereum/parity-ethereum/blob/55c90d4016505317034e3e98f699af07f5404b63/ethcore/src/client/client.rs#L1206-L1233) used by `trace_call` and `trace_callMany`. That path disabled nonce checks and used the requested block's header; it treated simulations as extra-block execution rather than pool admission. This explains the zero-fee precedent, but Parity predates `BASEFEE`. That is not precedent for preserving every environmental field: Parity's [call executors](https://github.com/openethereum/parity-ethereum/blob/55c90d4016505317034e3e98f699af07f5404b63/ethcore/src/client/client.rs#L1490-L1538) also replaced the gas limit with U256::max_value(). Preserving the selected block environment is an explicit modern contract choice.

[EIP-1559](https://eips.ethereum.org/EIPS/eip-1559#specification) makes the block base fee a separate environmental value and defines `GASPRICE` from the effective transaction price. The H15 probes show why a client should not make a zero-fee simulation succeed by silently changing the selected block's BASEFEE. pre-1559 Parity behavior cannot settle the modern relationship among zero-fee unsigned calls, typed fee fields, `GASPRICE` and simulated balance changes. The draft needs those observable rules, especially for `trace_callMany`, to make the proposed behavior precise; history does not decide these modern rules.

Reth's [unsigned-call environment](https://github.com/paradigmxyz/reth/blob/03cb186c1d36eebbacc7bda08f36e25711d0804e/crates/rpc/rpc-eth-api/src/helpers/call.rs#L876-L906) disables base-fee validation and fee charging, then sets the EVM block base fee to zero when the call's gas price is zero. Both [trace_call](https://github.com/paradigmxyz/reth/blob/03cb186c1d36eebbacc7bda08f36e25711d0804e/crates/rpc/rpc/src/trace.rs#L98-L109) and [trace_callMany](https://github.com/paradigmxyz/reth/blob/03cb186c1d36eebbacc7bda08f36e25711d0804e/crates/rpc/rpc/src/trace.rs#L149-L169) use this call setup. In the pinned [zero-fee](../cases/coverage/model-environment-free.md) probe, the tested release and development builds return GASPRICE 0 and BASEFEE 0 although the selected block's base fee is 765625000 wei. In the [priced](../cases/coverage/model-environment.md) probe, they return the supplied GASPRICE of 2 gwei and the original BASEFEE, but stateDiff shows no gas-fee debit. These are implementation observations, not client-team agreement; the callMany fixture confirms zero-fee execution but does not independently probe its BASEFEE opcode value.

It covers ordinary unsigned execution-gas simulations at a block with base fee B > 0, without block overrides or blob-fee fields; other request requirements still apply. The positive EIP-1559 cases assume a valid priority-fee cap no greater than the total cap. Both trace_call and trace_callMany use the fee paths described here.

Nethermind’s [ShouldValidateGas](https://github.com/NethermindEth/nethermind/blob/afd6a6dfbbef785afa48cb4a3a09706b5b6cf2ca/src/Nethermind/Nethermind.Evm/TransactionProcessing/TransactionProcessor.cs#L1105-L1205) enables fee validation whenever either fee cap is nonzero, even when the trace path skips other transaction checks. BuyGas then checks the block base fee and funding and deducts the upfront gas payment. Thus its comments saying traces do not charge fees do not describe priced calls.

Besu’s trace methods use [transactionSimulator validation](https://github.com/besu-eth/besu/blob/f9572aa82a2dadb3dd1b218d3ca97101540faf97/ethereum/api/src/main/java/org/hyperledger/besu/ethereum/api/jsonrpc/internal/methods/AbstractTraceByBlock.java#L121-L123), which rejects underpriced execution; its processor [deducts gas upfront](https://github.com/besu-eth/besu/blob/f9572aa82a2dadb3dd1b218d3ca97101540faf97/ethereum/core/src/main/java/org/hyperledger/besu/ethereum/mainnet/MainnetTransactionProcessor.java#L254-L257) and [settles refunds and beneficiary rewards](https://github.com/besu-eth/besu/blob/f9572aa82a2dadb3dd1b218d3ca97101540faf97/ethereum/core/src/main/java/org/hyperledger/besu/ethereum/mainnet/MainnetTransactionProcessor.java#L530-L609).

Reth’s legacy/EIP-1559 distinction originates in its locked [alloy-evm 0.39.0 dependency](https://github.com/paradigmxyz/reth/blob/9b8e2480feb8514a0b31279bf25eaa30dfd38d8a/Cargo.lock#L310-L313). The [fee normalizer](https://github.com/alloy-rs/alloy-evm/blob/ba6f83b80aba8cf005175f4d776d8b90796c72d9/crates/evm/src/rpc/fees.rs#L53-L109) accepts legacy gasPrice directly, but rejects a supplied nonzero EIP-1559 fee cap below the block base fee. Reth disables the later EVM base-fee check and gas-fee charging for unsigned calls.

Erigon instead [validates the fee cap](https://github.com/erigontech/erigon/blob/e26d9bd4056586e004488c31b561fb2663d46019/execution/protocol/txn_executor.go#L323-L329), while gasBailout [skips the sender debit](https://github.com/erigontech/erigon/blob/e26d9bd4056586e004488c31b561fb2663d46019/execution/protocol/txn_executor.go#L233-L247) without disabling the [beneficiary tip](https://github.com/erigontech/erigon/blob/e26d9bd4056586e004488c31b561fb2663d46019/execution/protocol/txn_executor.go#L750-L765). Fee validation and simulated payment therefore need separate assertions.

Omission and explicit zero are not interchangeable across clients. With all execution-fee fields omitted, [Nethermind](https://github.com/NethermindEth/nethermind/blob/afd6a6dfbbef785afa48cb4a3a09706b5b6cf2ca/src/Nethermind/Nethermind.Facade/Eth/RpcTransaction/LegacyTransactionForRpc.cs#L110-L114), [Reth](https://github.com/alloy-rs/alloy-evm/blob/ba6f83b80aba8cf005175f4d776d8b90796c72d9/crates/evm/src/rpc/fees.rs#L92-L101) and the [Geth draft fork](https://github.com/banteg/go-ethereum/blob/c36ee43e3827331276d045bd56d1297e4c3c9b15/internal/ethapi/transaction_args.go#L441-L455) default to zero; [Besu](https://github.com/besu-eth/besu/blob/f9572aa82a2dadb3dd1b218d3ca97101540faf97/ethereum/core/src/main/java/org/hyperledger/besu/ethereum/transaction/TransactionSimulator.java#L608-L617) and [Erigon](https://github.com/erigontech/erigon/blob/e26d9bd4056586e004488c31b561fb2663d46019/rpc/jsonrpc/trace_adhoc.go#L188-L211) default to the block base fee. An explicit maxFeePerGas 0 / maxPriorityFeePerGas 0 pair is accepted as zero-price execution by Nethermind, Reth and the Geth fork; Reth still changes BASEFEE to zero. Besu rejects the pair. Erigon replaces the pair with the block base fee and executes with GASPRICE = B. A zero priority fee alone is not a zero total fee.

For comparison, upstream Geth 920c0777 exposes these simulations through eth_call/debug_traceCall. Its [fee validation](https://github.com/ethereum/go-ethereum/blob/920c07774c65ebb3023536f85df642c44478b540/core/state_transition.go#L573-L588) exempts an all-zero fee pair and rejects positive prices below base fee, but [eth_call](https://github.com/ethereum/go-ethereum/blob/920c07774c65ebb3023536f85df642c44478b540/internal/ethapi/api.go#L795-L803) and [debug_traceCall](https://github.com/ethereum/go-ethereum/blob/920c07774c65ebb3023536f85df642c44478b540/eth/tracers/api.go#L956-L960) also set the opcode-visible BASEFEE to zero for zero-price execution. The draft fork’s trace namespace [preserves the selected block environment](https://github.com/banteg/go-ethereum/blob/c36ee43e3827331276d045bd56d1297e4c3c9b15/eth/tracers/trace_namespace.go#L375-L390).

## Decision needed

Agree the explicit zero-fee exemption and rejection of positive prices below base fee, then align environment preservation and simulated accounting. Specify omitted and incomplete fee-field defaults separately. Add direct legacy/EIP-1559 boundary probes and mixed free/priced callMany probes; the source comparison above does not extend the captured runtime coverage. The model-environment fixture returns BASEFEE as the second 32-byte output word, at byte offset 32.
