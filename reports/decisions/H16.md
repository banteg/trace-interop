# Fee accounting and sequential state diffs

**Question:** Which fee payments does a transaction's stateDiff report, and where do block-level balance changes go?

H16 · Spec decision / likely accounting bug · [All decisions](../../decisions/README.md)

**Status: ⚪ Under review** · [Status definitions](../../decisions/README.md#status-key)

No policy conclusion has been recorded. Implementation observations below do not establish client-team agreement.

[Client positions](../../decisions/README.md#client-positions): none recorded.

## Recommendation

For signed/raw and mined replay, report the complete actual transition: the sender pays value, gasUsed times the effective gas price and blobGasUsed times the blob base fee; base and blob fees are burned or credited to a chain-defined collector; the tip goes to the fee recipient. For unsigned calls use H15’s policy. Block-level operations (system calls, withdrawals, rewards) belong to no transaction’s stateDiff, so concatenated diffs do not reconstruct the block post-state. In trace_callMany every item is a separate transaction: EIP-2200/3529 original storage values, EIP-2929 access sets, EIP-1153 transient storage, the refund counter and the EIP-6780 same-transaction scope start afresh, while all items share one block environment (NUMBER and TIMESTAMP do not advance). The first item runs against the same state and environment as trace_call at the selected block. Each result describes its own transition from the preceding item’s post-state; reverted EVM writes roll back, while fork-defined transaction-level nonce and fee effects survive. If any decoded item fails validation, return one error and no partial results. A client SHOULD include the failing item’s zero-based index in error.data.index; if present, the index MUST identify the failing item. Malformed parameters need not include an item index (-32602 recommended). A server may cap items or total gas only with an explicit error (-38026 recommended), never by truncating.

A state diff should be internally coherent and reconstructible; an ordered multi-call simulation should have one predictable state timeline.

## Background

Parity's [multi-call executor](https://github.com/openethereum/parity-ethereum/blob/55c90d4016505317034e3e98f699af07f5404b63/ethcore/src/client/client.rs#L1518-L1538) applies each call to one mutable state in order. Its [virtual-call helper](https://github.com/openethereum/parity-ethereum/blob/55c90d4016505317034e3e98f699af07f5404b63/ethcore/src/client/client.rs#L1218-L1237) clones state immediately before a requested state diff, so each result describes that call relative to the preceding call's post-state. The [OpenEthereum multi-call guide](https://openethereum.github.io/JSONRPC-trace-module#trace_callmany) describes the same dependent-call purpose. This is stronger historical grounding than treating each result as an independent `trace_call` from the original block.

Parity's pre-1559 [transaction finalizer](https://github.com/openethereum/parity-ethereum/blob/55c90d4016505317034e3e98f699af07f5404b63/ethcore/machine/src/executive.rs#L1160-L1175) refunded the sender and credited the block author with fees. [EIP-1559](https://eips.ethereum.org/EIPS/eip-1559#specification) later split the effective gas price into a burned base fee and a beneficiary tip. Thus replay and signed raw traces should reflect the fork-correct actual state transition, while unsigned calls need the separate H15 fee policy. The pinned client state-diff sources and linked cases test the modern result; Parity alone cannot establish post-1559 accounting.

### Revised recommendation (2026-09-24 source review)

The previous recommendation said callMany diffs are sequential but not that each item is a separate transaction, what state the first item starts from, or how an item’s validation failure is reported, and its fee sentence omitted blob fees and fee collectors. Erigon and Reth return one error for an invalid item; Besu nests an error object inside `result` and Nethermind streams earlier items before truncating (H25); only Erigon names the index, in message text. All four reuse one header for every item, matching Parity and eth_simulateV1. The new rules move Besu, whose `TraceCallMany` commits each call into a shared updater without marking a transaction boundary ([TraceCallMany.java](https://github.com/besu-eth/besu/blob/07f0a4b2f832257842db71eacf4bca584f87fafe/ethereum/api/src/main/java/org/hyperledger/besu/ethereum/api/jsonrpc/internal/methods/TraceCallMany.java#L125-L142)), so a later call’s SSTORE uses the pre-bundle original value: its second `initial/call-many-priced` call uses 5,600 gas less than on every other build, and the reverted write in `a/many-storage-write-revert-read` 2,800 less. They also move Erigon’s historical trace_callMany, which reads a different state from trace_call (H28), and every client for the index in `error.data`. All nine builds already include the blob fee in the sender’s debit on `forks/replay-56`, and no transaction diff contains system-call, withdrawal or request-dequeue writes. See [statediff §1, §4, §8 and §9](../../docs/source-review/statediff.md) and [simulation §4](../../docs/source-review/simulation.md).

### Settled details (2026-09-24, Geth implementation)

A malformed item fails JSON-RPC parameter decoding before the method runs, so no implementation can attach an item index to it; the index requirement applies to decoded items that fail validation. The index is carried as `error.data.index`.

### Divergent-decisions review (2026-09-26)

The [review](../../docs/reviews/2026-09-26-divergent-decisions/H14-H15-H16.md) confirmed the accounting rules: replay and raw fee accounting is identical across all 11 builds (Erigon 3.7.0’s raw diff is fixed by #24328), no transaction diff carries block-level writes, and callMany items start afresh everywhere except Besu (#11365). One error with no partial results has Erigon, Reth, Parity and eth_simulateV1 behind it. `error.data.index` is new behavior rather than existing practice: Erigon’s "first run for txIndex N" message is its only precedent. It is kept because every implementation already loops by index and H14 rules out text matching, and it is the minimal machine-readable equivalent of eth_simulateV1’s per-call error objects under a one-error rule.

### Grandfathering revision (2026-09-30)

Keep one error without partial results and fresh transaction semantics for each batch item. Make error.data.index recommended rather than mandatory: no native implementation currently supplies it. Missing structured diagnostics do not change execution portability; a supplied index must still identify the failing item. See the [client review](../../docs/reviews/2026-09-30-open-policy-grandfathering/README.md).

## Decision needed

`probes-prague` measures cross-item transient storage, warm sets, original storage values and EIP-6780 scope with gas-deriving programs, and H28 has the callMany twin of the historical beacon-root call. The mined-probes replays pin exact SSTORE refunds (including the one-fifth cap), a blob fee and same-transaction SELFDESTRUCT burns. Add a refund-counter reset probe (restore a slot written by the previous item), and model fee collectors before assigning chains that use them.
