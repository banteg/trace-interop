# H17 — New-account stateDiff encoding

**Disposition:** Spec decision / likely serializer fix. Proposal, awaiting client review.

## Proposed behavior

Make account existence explicit: + for fields of a newly created account (including empty code and nonce zero), - for deletion, * for a changed existing value, = for unchanged existing fields. If an address already existed with empty code, do not mark it as newly created.

## Rationale

Absent and existing-but-empty are different states; consumers should be able to reconstruct the change without guessing.

## Open questions

Review account-creation markers separately from the prefunded-empty-account check. Agree the existence model across balance, code, nonce and storage deltas.
