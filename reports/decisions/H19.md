## Recommendation

Record the bytecode actually executed in each frame: initcode for creation, resolved implementation code for delegation, and the relevant code source for delegatecall/callcode. Do not populate it from an address-only pre-state lookup after tracing.

The operations must be decodable against the bytes in their own frame.

## Background

Parity's [VM tracer](https://github.com/openethereum/parity-ethereum/blob/55c90d4016505317034e3e98f699af07f5404b63/ethcore/trace/src/executive_tracer.rs#L277-L296) stores the `code` bytes passed when an execution subtrace begins, and the [executor](https://github.com/openethereum/parity-ethereum/blob/55c90d4016505317034e3e98f699af07f5404b63/ethcore/machine/src/executive.rs#L953-L966) passes the chosen action's code, not a later address lookup. This explains the original `vmTrace.code` field as executing bytecode. For CREATE that is initcode, while H10's `result.code` is deployed runtime code.

[EIP-7702](https://eips.ethereum.org/EIPS/eip-7702#delegation-indicator) adds delegation-code resolution after Parity's era: execution follows one indicated target and stops after that first hop, while external code-reading opcodes inspect the indicator itself. The trace therefore needs the resolved executed bytes in a delegated frame, not the authority's 23-byte indicator or a stale pre-state lookup. The pinned [Reth trace builder](https://github.com/paradigmxyz/reth/blob/03cb186c1d36eebbacc7bda08f36e25711d0804e/crates/rpc/rpc/src/trace.rs) and [inspector dependency](https://github.com/paradigmxyz/revm-inspectors/blob/453c67d7ccdf51327c9e7687ac6ba0b8651e7f87/src/tracing/builder/parity.rs) are the relevant modern path for the linked missing-initcode case.

## Decision needed

Fix bytecode population separately from the already-retested instruction deltas. Add EIP-7702 one-hop controls: a delegation target that itself delegates must not be followed recursively, and delegation to a precompile executes empty code rather than the native precompile.
