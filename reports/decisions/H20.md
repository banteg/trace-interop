## Recommendation

mem is the post-operation contents of the memory range the opcode’s operands designate: MSTORE and MLOAD [off, off+32), MSTORE8 [off, off+1), and the destination of CALLDATACOPY, CODECOPY, EXTCODECOPY, RETURNDATACOPY and MCOPY. For the CALL family the range starts at the output offset and is either the full output window [outOff, outOff+outSize) (preferred, as Parity) or exactly the bytes the call copied, [outOff, outOff+min(outSize, RETURNDATASIZE)); consumers may apply mem as a write under either, but must not infer RETURNDATASIZE from its length. It is null when that range is empty or the opcode designates none (RETURN, REVERT, LOG*, KECCAK256, CREATE*). cost is the total gas deducted from the caller when the operation starts, including gas made available to a child frame (CALL family: the 63/64-capped forwarded gas, excluding the value stipend; CREATE family: all but 1/64), also when the call or creation fails its balance or depth precheck and that gas is returned at once. ex.used is the caller’s remaining gas after the operation, including unused child gas returned (after a failed precheck: the forwarded gas and any value stipend). An operation that began executing and halted exceptionally is present with ex: null and sub: null; its cost is an implementation-defined non-negative integer (the full cost it required, or the part charged before the halt) and has no accounting meaning, since a halted frame returns no gas. Operations rejected before execution (undefined opcodes including the designated invalid 0xFE, stack underflow or overflow) are omitted, and there is no synthetic STOP, so every pc lies inside code. push is the top k stack words after execution, deepest first, where k is the number of words the opcode leaves in place of its inputs (DUPn and SWAPn n+1, CALL and CREATE 1 after the child returns). store is set only by SSTORE, from its key and value operands as quantities, whenever the SSTORE completes, even if the value is unchanged; TSTORE and SLOAD never set it. A selected vmTrace is always an object. An operation that entered a child frame, including precompile and empty-code targets, has that frame’s trace as sub ({code: "0x", ops: []} if no instruction ran); operations that entered no frame (failed precheck, SELFDESTRUCT) have sub: null.

Same-step effects let consumers follow execution without shifting writes between opcodes. Operand-derived ranges need no return-data dependency and match Parity, Erigon, Nethermind and Besu for MLOAD. For a CALL, the full window (Parity, Erigon) and the copied prefix (Besu, revm-inspectors) both reconstruct memory exactly when applied as writes, and no known consumer distinguishes them, so either is accepted. For an operation that entered a child frame, used = previous used − cost + child leftover (0 if the child halted) is checkable without opcode knowledge; a CALL or CREATE that fails its precheck instead gets its forwarded gas (and a value call’s stipend) back directly. The cost of a halted operation depends on where an interpreter detects the fault, and nothing consumes it.

## Background

Parity's [interpreter](https://github.com/openethereum/parity-ethereum/blob/55c90d4016505317034e3e98f699af07f5404b63/ethcore/evm/src/interpreter/mod.rs#L348-L405) calls the VM tracer before an opcode with its cost and reported memory region, then after the opcode with the current remaining gas, pushed stack words and memory. The [VM tracer](https://github.com/openethereum/parity-ethereum/blob/55c90d4016505317034e3e98f699af07f5404b63/ethcore/trace/src/executive_tracer.rs#L241-L274) stores that after-step gas in the value serialized as `ex.used` and extracts that post-step memory slice. Its internal field is named `gas_used`, but the passed value is remaining gas; the recommendation follows the execution path rather than the misleading name.

[EIP-5656](https://eips.ethereum.org/EIPS/eip-5656#semantics) introduced MCOPY after Parity's codebase and defines it as an actual destination-memory write, including overlapping copies. Erigon handles MCOPY's destination ([trace_adhoc.go](https://github.com/erigontech/erigon/blob/3b4861d10387ca3e19f7b16d1b8c0ec1fcd616cd/rpc/jsonrpc/trace_adhoc.go#L593-L596)): development build e26d9bd4 reports it on `a/call-mcopy` and `coverage/model-mcopy-overlap`, and only release 3.6.1 misses it. The pinned [Besu VM generator](https://github.com/besu-eth/besu/blob/d997aad7b3be6333464c0687d3761c568ee63524/ethereum/api/src/main/java/org/hyperledger/besu/ethereum/api/jsonrpc/internal/results/tracing/vm/VmTraceGenerator.java) still omits it.

Parity's [memory-region calculation](https://github.com/openethereum/parity-ethereum/blob/55c90d4016505317034e3e98f699af07f5404b63/ethcore/evm/src/interpreter/mod.rs#L472-L493) included MLOAD and the entire requested CALL output window. Those were post-step snapshots of the operand range, not exclusively writes. Erigon ([trace_adhoc.go](https://github.com/erigontech/erigon/blob/3b4861d10387ca3e19f7b16d1b8c0ec1fcd616cd/rpc/jsonrpc/trace_adhoc.go#L593-L596)), Nethermind and Besu ([VmTraceGenerator.java](https://github.com/besu-eth/besu/blob/07f0a4b2f832257842db71eacf4bca584f87fafe/ethereum/api/src/main/java/org/hyperledger/besu/ethereum/api/jsonrpc/internal/results/tracing/vm/VmTraceGenerator.java#L235)) all still report MLOAD this way. For the CALL output window there is no majority: Parity and Erigon report the full window; the Geth draft and revm-inspectors main report the returned bytes; Besu reports the returned bytes or a value copied from the calling frame’s final RETURN ([VmTraceGenerator.java](https://github.com/besu-eth/besu/blob/07f0a4b2f832257842db71eacf4bca584f87fafe/ethereum/api/src/main/java/org/hyperledger/besu/ethereum/api/jsonrpc/internal/results/tracing/vm/VmTraceGenerator.java#L314-L324)); Nethermind reports nothing.

### Revised recommendation (2026-09-24 source review)

The previous recommendation narrowed `mem` to bytes actually written, which gave MLOAD no memory delta and trimmed a short CALL return, and deferred the call/return gas boundary and failed-operation conventions to fixtures. The narrowing departed from Parity and from all three established implementations for MLOAD; on the dedicated model cases it was the only H20 difference for Erigon e26d9bd4 and Nethermind 641592d2. The revision reverses it. Erigon, Nethermind and Besu now conform on MLOAD, while our Geth draft fork and unreleased revm-inspectors main, which followed the narrowing, must change. For the CALL output window Erigon already conforms; Nethermind, Besu, the Geth draft and revm-inspectors main change.

The gas, halt and step rules are Parity’s ([mod.rs](https://github.com/openethereum/parity-ethereum/blob/55c90d4016505317034e3e98f699af07f5404b63/ethcore/evm/src/interpreter/mod.rs#L336-L415)) and most clients already follow them; on the replay-tree root CALL, Erigon, Nethermind and the Geth draft all report cost 71,624 and used 569,571. They move: Besu (stipend in value-CALL cost, precompile execution cost instead of forwarded gas, and cost = all remaining gas with used 0 for a failed operation); the Geth draft and Nethermind (CREATE cost without forwarded gas; Nethermind’s streaming tracer loses its base tracer’s addition); Erigon (keeps `ex`, and even `store`, for a failed static SSTORE) and Nethermind (deletes most failed operations); the synthetic STOP emitted by Erigon, the Geth draft and Reth; Nethermind’s DUPn `push` (n words, captured before the copy); Nethermind’s `store` (present only when stateDiff is also selected); revm-inspectors main’s `store` (set on a cold SLOAD and missing on a warm unchanged SSTORE; Reth 0.43.0 never sets it); the Geth draft’s null vmTrace for an EOA target and null `sub` for precompile and empty-code targets (also revm-inspectors main); and Erigon’s extra `sub` on SELFDESTRUCT and on calls that fail their precheck. See [vmtrace A1–A6, B6 and C1–C8](../../docs/source-review/vmtrace.md).

### Divergent-decisions review (2026-09-26)

The [review](../../docs/reviews/2026-09-26-divergent-decisions/H08-H20.md) kept almost every rule and changed two. No three native clients share either CALL-family `mem` range: Parity and Erigon (and Polygon Bor, which copies Erigon) report the full output window, Besu and revm-inspectors main the copied bytes (revm’s clamp came from our own #504 under the superseded narrowing), and Nethermind nothing. Both reconstruct memory exactly as writes and no consumer found (Otterscan, ApeWorX evm-trace, cryo, flashboys2) distinguishes them, so both are accepted and the window is preferred. The cost of an operation that halts depends on interpreter ordering: for the same static-context SSTORE Parity charges the SSTORE cost, Geth, Erigon and revm report 0 and Besu all remaining gas, and for an out-of-gas MLOAD revm reports only the static 3. It is now implementation-defined. The failed-precheck cost was ambiguous rather than split: Parity, Erigon, Reth and the Geth draft include the forwarded gas, which is returned at once, so the nested-gas relation holds only for operations that entered a frame. MLOAD `mem` is a real consensus (Parity, Erigon, Nethermind, Besu), which leaves revm #504’s MLOAD omission as the outlier. Besu’s multi-word `push`, earlier suspected from source to be top-first, is deepest-first on `probes-prague/vm-push-order`.

### EIP-8141 frame transactions (2026-09-27)

[execution-apis#909](https://github.com/ethereum/execution-apis/pull/909) gives a frame transaction a synthetic `vmTrace` root with `code: 0x` and one operation per frame that entered the EVM, whose `pc` is the frame index, `cost` the frame gas limit and `sub` the frame's own trace. That breaks this decision's rule that every `pc` lies inside the code; the [review comment](https://github.com/ethereum/execution-apis/pull/909#issuecomment-5856338610) proposes an explicit exception for frame transactions rather than changing the container. Untested until a second client implements EIP-8141.

Supporting controls (not standalone assertions): [repeat/debug-gas7400-opcodes](../cases/repeat/debug-gas7400-opcodes.md).

## Decision needed

The local invariants check pc bounds, the nested-gas relation for calls and creations, subtrace placement and the MLOAD and CALL memory ranges. `probes-prague` exercises DUP/SWAP push with distinct values, SSTORE/SLOAD/TSTORE/TLOAD store (with and without stateDiff), code that runs off its end and precheck-failure subs. Still add a short CALL return over a nonzero tail, and EOA, precompile and empty-code targets. `a/call-gas7400` carries no H20 assertions, so only `repeat/call-gas7400` catches Nethermind’s rewrite of a 7400 cost to 9700.
