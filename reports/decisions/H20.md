## Recommendation

mem is the post-operation contents of the memory range the opcode’s operands designate: MSTORE and MLOAD [off, off+32), MSTORE8 [off, off+1), the destination of CALLDATACOPY, CODECOPY, EXTCODECOPY, RETURNDATACOPY and MCOPY, and the full CALL-family output window. It is null when that range is empty or the opcode designates none (RETURN, REVERT, LOG*, KECCAK256, CREATE*). cost is the total gas deducted from the caller when the operation starts, including gas made available to a child frame (CALL family: the 63/64-capped forwarded gas, excluding the value stipend; CREATE family: all but 1/64). ex.used is the caller’s remaining gas after the operation, including unused child gas returned. An operation that began executing and halted exceptionally is present with its pre-execution cost, ex: null and sub: null; operations rejected before execution (undefined opcodes including the designated invalid 0xFE, stack underflow or overflow) are omitted, and there is no synthetic STOP, so every pc lies inside code. push is the top k stack words after execution, deepest first, where k is the number of words the opcode leaves in place of its inputs (DUPn and SWAPn n+1, CALL and CREATE 1 after the child returns). store is set only by SSTORE, from its key and value operands as quantities, whenever the SSTORE completes, even if the value is unchanged; TSTORE and SLOAD never set it. A selected vmTrace is always an object. An operation that entered a child frame, including precompile and empty-code targets, has that frame’s trace as sub ({code: "0x", ops: []} if no instruction ran); operations that entered no frame (failed precheck, SELFDESTRUCT) have sub: null.

Same-step effects let consumers follow execution without shifting writes between opcodes. An operand-derived range needs no return-data dependency and is exactly what Parity and three established clients report; a consumer that applies mem as a write reconstructs memory under either rule. The gas and halt rules make the nested-gas relation used = previous used − cost + child leftover checkable without opcode knowledge.

## Background

Parity's [interpreter](https://github.com/openethereum/parity-ethereum/blob/55c90d4016505317034e3e98f699af07f5404b63/ethcore/evm/src/interpreter/mod.rs#L348-L405) calls the VM tracer before an opcode with its cost and reported memory region, then after the opcode with the current remaining gas, pushed stack words and memory. The [VM tracer](https://github.com/openethereum/parity-ethereum/blob/55c90d4016505317034e3e98f699af07f5404b63/ethcore/trace/src/executive_tracer.rs#L241-L274) stores that after-step gas in the value serialized as `ex.used` and extracts that post-step memory slice. Its internal field is named `gas_used`, but the passed value is remaining gas; the recommendation follows the execution path rather than the misleading name.

[EIP-5656](https://eips.ethereum.org/EIPS/eip-5656#semantics) introduced MCOPY after Parity's codebase and defines it as an actual destination-memory write, including overlapping copies. Erigon handles MCOPY's destination ([trace_adhoc.go](https://github.com/erigontech/erigon/blob/3b4861d10387ca3e19f7b16d1b8c0ec1fcd616cd/rpc/jsonrpc/trace_adhoc.go#L593-L596)): development build e26d9bd4 reports it on `a/call-mcopy` and `coverage/model-mcopy-overlap`, and only release 3.6.1 misses it. The pinned [Besu VM generator](https://github.com/besu-eth/besu/blob/d997aad7b3be6333464c0687d3761c568ee63524/ethereum/api/src/main/java/org/hyperledger/besu/ethereum/api/jsonrpc/internal/results/tracing/vm/VmTraceGenerator.java) still omits it.

Parity's [memory-region calculation](https://github.com/openethereum/parity-ethereum/blob/55c90d4016505317034e3e98f699af07f5404b63/ethcore/evm/src/interpreter/mod.rs#L472-L493) included MLOAD and the entire requested CALL output window. Those were post-step snapshots of the operand range, not exclusively writes. Erigon ([trace_adhoc.go](https://github.com/erigontech/erigon/blob/3b4861d10387ca3e19f7b16d1b8c0ec1fcd616cd/rpc/jsonrpc/trace_adhoc.go#L593-L596)), Nethermind and Besu ([VmTraceGenerator.java](https://github.com/besu-eth/besu/blob/07f0a4b2f832257842db71eacf4bca584f87fafe/ethereum/api/src/main/java/org/hyperledger/besu/ethereum/api/jsonrpc/internal/results/tracing/vm/VmTraceGenerator.java#L235)) all still report MLOAD this way. For the CALL output window there is no majority: Parity and Erigon report the full window; the Geth draft and revm-inspectors main report the returned bytes; Besu reports the returned bytes or a value copied from the calling frame’s final RETURN ([VmTraceGenerator.java](https://github.com/besu-eth/besu/blob/07f0a4b2f832257842db71eacf4bca584f87fafe/ethereum/api/src/main/java/org/hyperledger/besu/ethereum/api/jsonrpc/internal/results/tracing/vm/VmTraceGenerator.java#L314-L324)); Nethermind reports nothing.

### Revised recommendation (2026-09-24 source review)

The previous recommendation narrowed `mem` to bytes actually written, which gave MLOAD no memory delta and trimmed a short CALL return, and deferred the call/return gas boundary and failed-operation conventions to fixtures. The narrowing departed from Parity and from all three established implementations for MLOAD; on the dedicated model cases it was the only H20 difference for Erigon e26d9bd4 and Nethermind 641592d2. The revision reverses it. Erigon, Nethermind and Besu now conform on MLOAD, while our Geth draft fork and unreleased revm-inspectors main, which followed the narrowing, must change. For the CALL output window Erigon already conforms; Nethermind, Besu, the Geth draft and revm-inspectors main change.

The gas, halt and step rules are Parity’s ([mod.rs](https://github.com/openethereum/parity-ethereum/blob/55c90d4016505317034e3e98f699af07f5404b63/ethcore/evm/src/interpreter/mod.rs#L336-L415)) and most clients already follow them; on the replay-tree root CALL, Erigon, Nethermind and the Geth draft all report cost 71,624 and used 569,571. They move: Besu (stipend in value-CALL cost, precompile execution cost instead of forwarded gas, and cost = all remaining gas with used 0 for a failed operation); the Geth draft and Nethermind (CREATE cost without forwarded gas; Nethermind’s streaming tracer loses its base tracer’s addition); Erigon (keeps `ex`, and even `store`, for a failed static SSTORE) and Nethermind (deletes most failed operations); the synthetic STOP emitted by Erigon, the Geth draft and Reth; Nethermind’s DUPn `push` (n words, captured before the copy) and Besu’s top-first multi-word `push` (source only); Nethermind’s `store` (present only when stateDiff is also selected); revm-inspectors main’s `store` (set on a cold SLOAD and missing on a warm unchanged SSTORE; Reth 0.43.0 never sets it); the Geth draft’s null vmTrace for an EOA target and null `sub` for precompile and empty-code targets (also revm-inspectors main); and Erigon’s extra `sub` on SELFDESTRUCT and on calls that fail their precheck. See [vmtrace A1–A6, B6 and C1–C8](../../docs/source-review/vmtrace.md).

Supporting controls (not standalone assertions): [repeat/debug-gas7400-opcodes](../cases/repeat/debug-gas7400-opcodes.md).

## Decision needed

The local invariants check pc bounds, the nested-gas relation for calls and creations, subtrace placement and the MLOAD and CALL memory ranges. Add fixtures that exercise them: DUP/SWAP push with distinct values, a vmTrace SSTORE fixture (warm unchanged write, cold read), code that runs off its end, a short CALL return over a nonzero tail, and EOA, precompile and empty-code targets.
