## Recommendation

Compare account existence before and after the execution. For present-to-absent accounts, use deletion markers for balance, nonce and code, and report storage: {}; the account’s - implies that all storage is wiped, so no slot is listed. After EIP-6780 a pre-existing contract normally survives SELFDESTRUCT, so do not report code deletion. An account absent at both endpoints has no net account diff, even if created and destroyed during execution.

Deletion and a zero balance with retained code are observably different states. Apply the rules of the selected block.

## Background

Parity's [original account diff](https://github.com/openethereum/parity-ethereum/blob/55c90d4016505317034e3e98f699af07f5404b63/ethcore/pod/src/account.rs#L103-L140) distinguishes a present account becoming absent (`Died` for balance, nonce, code and each prior storage slot supplied to that helper; in practice none were, see below) from an account that remains present with changed values. Its [transaction finalizer](https://github.com/openethereum/parity-ethereum/blob/55c90d4016505317034e3e98f699af07f5404b63/ethcore/machine/src/executive.rs#L1132-L1181) actually removed SELFDESTRUCT accounts at the end of execution under those pre-Cancun rules. The deletion markers therefore describe account existence, not merely a zeroed balance.

[EIP-6780](https://eips.ethereum.org/EIPS/eip-6780) deliberately changed that premise: SELFDESTRUCT normally transfers the balance without deleting a pre-existing account's code or storage, preserving deletion only for a contract created in the same transaction. This explains why the selected block's fork rules determine the stateDiff, and why the Nethermind/Reth pre-Cancun missing code and nonce markers are meaningful. `stateDiff` compares the before and after account snapshots. A contract created and destroyed within the same transaction can leave no account at either endpoint, so even genuine transient deletion need not produce a `Died` entry; an execution trace is needed to see that event. A prefunded address, however, existed before creation; deletion at that address can require a net deletion entry.

Parity in fact emitted `storage: {}` for a deleted account. [Account::to_pod](https://github.com/openethereum/parity-ethereum/blob/55c90d4016505317034e3e98f699af07f5404b63/ethcore/account-state/src/account.rs#L142-L157) exposes only `storage_changes`, and [state diff construction](https://github.com/openethereum/parity-ethereum/blob/55c90d4016505317034e3e98f699af07f5404b63/ethcore/account-state/src/state.rs#L868-L926) takes a killed account’s keys from the pre-state clone’s dirty changes plus the queried account, which is `None` after deletion and short-circuits. The pre-state clone is clean for `trace_call` and for a replay’s first transaction, so no slot reached the `Died` helper; only keys dirtied by earlier uncommitted calls in the same bundle or block could appear, which is a quirk. Besu ([StateTraceGenerator.java](https://github.com/besu-eth/besu/blob/07f0a4b2f832257842db71eacf4bca584f87fafe/ethereum/api/src/main/java/org/hyperledger/besu/ethereum/api/jsonrpc/internal/results/tracing/diff/StateTraceGenerator.java#L142)) and Erigon also report `{}`; Nethermind reports written slots as `*` to zero, the Geth draft written slots as `-`, and revm-inspectors main accessed nonzero slots as `-`.

Reth’s missing deletion markers are fixed upstream by [revm-inspectors #510](https://github.com/paradigmxyz/revm-inspectors/pull/510), merged into main but unreleased after 0.43.0, which Reth main still locks. Nethermind release 2.0.0 reports a pre-Cancun deletion as `*` to `null` for balance, nonce and code, which is schema-invalid rather than merely missing markers; the harness checks only code and nonce.

### Revised recommendation (2026-09-24 source review)

The previous recommendation left the enumeration of untouched prior slots open. The revision adopts `storage: {}`, which is deterministic, cheap, and what Parity, Besu and Erigon already report. It moves Nethermind (written slots as `*` to zero), the Geth draft (written slots as `-`) and revm-inspectors main (accessed nonzero slots as `-`). The current fixture account has no storage, so none of these differences is captured yet. See [statediff §6 and §11](../../docs/source-review/statediff.md).
