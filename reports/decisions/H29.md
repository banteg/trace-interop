# Precompile call-frame inclusion

**Question:** Which precompile calls appear as call frames?

H29 · Spec decision / client alignment · [All decisions](../../decisions/README.md)

**Status: ⚪ Under review** · [Status definitions](../../decisions/README.md#status-key)

No policy conclusion has been recorded. Implementation observations below do not establish client-team agreement.

[Client positions](../../decisions/README.md#client-positions): none recorded.

[Rule in the pinned draft](https://github.com/banteg/execution-apis/blob/e437815dba041158b7079bf149052fb7301f8419/docs-api/docs/trace-profile.md#precompile-frames-h29)

## Recommendation

Retain root precompile calls. Omit nested precompile frames with zero value; retain those with nonzero transferred or inherited value, whether successful or failed. A precompile is an address in the precompile set active at the executing block’s fork, so a zero-value call to an address before its precompile activates is an ordinary call and keeps its frame. A CALL-family call that fails its precheck (depth limit, insufficient balance) emits a frame with its action and error label, no result and no subtraces; the forwarded gas returns to the caller, which continues after pushing 0. A CREATE or CREATE2 that fails its precheck (depth limit, insufficient balance, nonce overflow) emits the same kind of frame before Amsterdam; from Amsterdam the check runs in the creating opcode and no frame is emitted. A CREATE address collision emits a create frame with error "Contract address collision" that consumes its gas. Number traceAddress and subtraces over the emitted tree. Keep caller VM return-memory effects even when a child frame is omitted.

The retained inherited-value exception is a compatibility choice, not a statement that DELEGATECALL transfers funds. Crossed-value CALL/CALLCODE fixtures confirm that Erigon, Reth and Nethermind use the explicit child value rather than the outer value. Besu still omits the nonzero-value child. The independent Geth draft implementation also matches these checks; it is not an independent vote for the policy. Precheck failures follow the call tracers of Geth, Erigon, Reth and Besu, which record the attempted call and its rejection; without the frame, the only record of a rejected value transfer is the zero the caller pushes.

## Background

Parity's [original ExecutiveTracer](https://github.com/openethereum/parity-ethereum/blob/55c90d4016505317034e3e98f699af07f5404b63/ethcore/trace/src/executive_tracer.rs#L41-L108) explicitly skipped only a non-root built-in call whose `ActionParams.value.value()` was zero. It incremented the parent's subtrace count and path only for retained frames; its success and failure callbacks both cleared the skip flag for an omitted built-in. That is the trace namespace's historical frame policy, rather than a consequence of whether the precompile did useful computation or succeeded.

The old [ActionValue definition](https://github.com/openethereum/parity-ethereum/blob/55c90d4016505317034e3e98f699af07f5404b63/ethcore/vm/src/action_params.rs#L29-L62) makes `value()` return either a transferred or an apparent value. A DELEGATECALL can therefore retain a frame because it inherits a nonzero apparent value even though it moves no funds. The pinned [Besu generator](https://github.com/besu-eth/besu/blob/d997aad7b3be6333464c0687d3761c568ee63524/ethereum/api/src/main/java/org/hyperledger/besu/ethereum/api/jsonrpc/internal/results/tracing/flat/FlatTraceGenerator.java#L280-L313) skips precompile calls during frame construction; the crossed outer/child value fixtures isolate the incompatibility. This inherited-value exception is a historical compatibility rule, not a value-transfer assertion.

### Revised recommendation (2026-09-24 source review)

The previous recommendation did not say which precompile set applies, or whether calls that fail their precheck emit frames. Parity’s builtin check is fork-aware ([executive_tracer.rs](https://github.com/openethereum/parity-ethereum/blob/55c90d4016505317034e3e98f699af07f5404b63/ethcore/trace/src/executive_tracer.rs#L44)), as are revm-inspectors and Erigon. Clients split 3/3 on prechecks: Parity ([mod.rs](https://github.com/openethereum/parity-ethereum/blob/55c90d4016505317034e3e98f699af07f5404b63/ethcore/evm/src/interpreter/mod.rs#L633-L637)), Besu and Nethermind emit no frame for a CALL that fails the depth or balance check, while Erigon, the Geth draft and Reth emit one with an error. Parity reported a CREATE collision as "Out of gas"; Nethermind emits no collision frame. Following Parity moves Erigon, the Geth draft and Reth for prechecks (Geth and Erigon already drop CREATE precheck frames from Amsterdam) and Nethermind for collisions. No fixture covers depth, nested insufficient balance or collisions yet. See [call-trace A4 and A8](../../docs/source-review/call-trace.md).

### Mainnet evidence: the Unchained Index (2026-09-26)

The TrueBlocks Unchained Index records an appearance for every address in `trace_block` output, including each frame's `from` and `to` ([uniq_appearances.go](https://github.com/TrueBlocks/trueblocks-chifra/blob/ff9df4fc2ae8e884304bd527b89e0486ccffa3e9/pkg/uniq/uniq_appearances.go#L66-L74)), so its published chunks show which precheck policy their builder followed. A port of those extraction rules, run against a Reth 2.6.0 mainnet node, reproduced 734,090 of the 734,091 appearances it derived in 1,000 random blocks of the published range (blocks 0–22,997,660, `trueblocks-core@v2.0.0-release`). The one difference is a precheck failure: transaction 54 of block 22,434,049 ([0xd4ec74e5…](https://etherscan.io/tx/0xd4ec74e5cd0cf2b770ec8d306dcc9c32271794fe6f51c80adeff0d92181e4bab)) ends with a CALL paying the fee recipient that fails with "Insufficient balance for transfer". Reth emits that frame; the published index has no appearance for it. A scan of 22,490 random blocks between 2.5M and 23.0M found 86 addresses whose only source is a precheck-failed CALL, among them the Uniswap routers in [0x687485de…](https://etherscan.io/tx/0x687485de22c6524922d1dec54bfd419596cce728a25d04fce2d36df9ac753c21) (block 10,977,969) and [0x07a4dc53…](https://etherscan.io/tx/0x07a4dc535a42e08c6bacdbd543d865e21561ead9da8dbf30e0e138b0717003f9) (block 12,581,371). None is in the published index. Chunks built locally with Reth 2.6.0 beyond block 22,997,660 contain all 11 such addresses found in 3,000 sampled blocks, about 0.4 per 100 blocks, so current Reth cannot reproduce the published chunks.

The same data identifies the builder. Addresses found only in revert output are indexed (at blocks 11.3M, 16.4M and 20.4M), which excludes OpenEthereum, which reported no `result` on failed frames, and Besu and Nethermind, which omit revert output. The missing precheck frames exclude Reth. Erigon fits both until v3.0: its `call` returned on the depth and balance checks ([v3.0.17 evm.go:189-199](https://github.com/erigontech/erigon/blob/7d3cab29f3741b567bce96012371e8dbbd402a5f/core/vm/evm.go#L189-L199)) before any tracer hook, and v3.1.0 (2025-09-16) moved `captureBegin` ahead of them ([v3.1.0 evm.go:209-230](https://github.com/erigontech/erigon/blob/4e2977042ee93ff4f95ed94a4dc8aa674bbbe06b/core/vm/evm.go#L209-L230)). The published chunks therefore record pre-3.1 Erigon behavior. Any continuation built with current Erigon or Reth adds these appearances, and so does any client that follows the revised rule below.

### Revised precheck rule (2026-09-26)

The previous recommendation followed Parity and emitted no frame for a failed precheck. It is reversed because the geth-style call tracers record the attempt. Geth has captured a call before its depth and balance checks since v1.14 ([#29189](https://github.com/ethereum/go-ethereum/pull/29189)). The review of [#27629](https://github.com/ethereum/go-ethereum/pull/27629) debated exactly this: one reviewer proposed starting the tracer after the precheck ("no gas no trace", [comment](https://github.com/ethereum/go-ethereum/pull/27629#discussion_r1277007296)), another argued that "it's a call that was executed, it was legitimately called by the smart contract" ([comment](https://github.com/ethereum/go-ethereum/pull/27629#discussion_r1277719870)), and the tracing maintainer made capturing the call "the first thing we do in `evm.Call/Create/...`" ([comment](https://github.com/ethereum/go-ethereum/pull/27629#discussion_r1311833716)). #29189 updated the callTracer and flatCallTracer fixtures to match; [`call_tracer_flat/skip_no_balance_error.json`](https://github.com/ethereum/go-ethereum/blob/064f37d6f67a012eea0bf8d410346fb1684004b4/eth/tracers/internal/tracetest/testdata/call_tracer_flat/skip_no_balance_error.json), written to assert the Parity-style skip, now expects the failed frame. Erigon adopted the same ordering in v3.1.0, revm-inspectors always recorded the attempt and labels it "Insufficient balance for transfer" in Parity output, and Besu's callTracer records it too; Nethermind omits it from both trace_* and its callTracer. The `-debug-callTracer` and `-debug-flatCallTracer` cases in `probes-prague` capture these tracers for the precheck probes.

Geth moved the CREATE precheck into the creating opcode from Amsterdam ([`chargeAccountCreation`](https://github.com/ethereum/go-ethereum/blob/920c07774c65ebb3023536f85df642c44478b540/core/vm/evm.go#L504-L541)), so a failed CREATE has no frame in its call tracers from that fork, while a failed CALL keeps one; the rule follows that split. The frame carries the only record of which call was rejected and why: in the mainnet transaction above, a bot's payment to the fee recipient failed for lack of balance. Its cost is compatibility with Parity-era output, including the published Unchained Index chunks. The revision changes Besu's and Nethermind's trace_* and the Geth draft, and Erigon's lowercase label is an H09 difference.

The depth limit is testable only before EIP-150: its 63/64 rule means reaching depth 1024 needs roughly (64/63)^1024 ≈ 10^7 times the per-frame gas, beyond any block or RPC gas cap. The forks fixture chain runs Homestead rules until block 4, where a CALL forwards exactly the gas it requests, so `probes-forks/depth-limit` runs a self-calling contract at block 3 for under a million gas; the deepest frame's CALL and CREATE both fail the depth check. A pre-release capture on all nine builds found the frames in Erigon and Reth, labelled "max call depth exceeded" and `CallTooDeep`, and none in Nethermind. Besu omits the failed CALL but reports the failed CREATE as a successful frame, the same defect as its balance precheck. The label "Max call depth exceeded" follows revm-inspectors' convention for post-Parity failures, Geth's error text capitalized, as with "Insufficient balance for transfer".

The mined calltree transaction (block 2) makes a nested zero-value CALL to the identity precompile between its CALLCODE and CREATE. Its trace_transaction, trace_block, unfiltered trace_filter and trace-mode replays must omit that frame, so a client whose mined and simulated traces use different frame policies is measured on both.

## Decision needed

Collect client positions on the revised precheck rule: Besu and Nethermind would add precheck frames to trace_*, and Nethermind also to its callTracer; Erigon and Reth already emit them, Erigon with a lowercase label. Add an Amsterdam CREATE precheck fixture once clients support the fork. Review the inherited DELEGATECALL exception as a compatibility choice, and add a zero-value call to 0x0a before Cancun and to 0x100 before Osaka. `probes-prague` covers a nested value CALL and CREATE beyond balance, the same calls through `debug_traceCall`, and a CREATE2 collision. The precompile-values corpus separates outer and child values, pre-funds zero-value creations with a preceding simulated transfer, and returns the call success bit. Parent error propagation remains a separate H24 issue.
