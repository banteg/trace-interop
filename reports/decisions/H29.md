# Precompile call-frame inclusion

H29 · Spec decision / client alignment · [All decisions](../README.md#decisions-to-review)

[Rule in the pinned draft](https://github.com/banteg/execution-apis/blob/e38fc96c9942f201b683e231f69432729d2737df/docs-api/docs/trace-profile.md#precompile-frames-h29)

## Recommendation

Retain root precompile calls. Omit nested precompile frames with zero value; retain those with nonzero transferred or inherited value, whether successful or failed. Number traceAddress and subtraces over the emitted tree. Keep caller VM return-memory effects even when a child frame is omitted.

The retained inherited-value exception is a compatibility choice, not a statement that DELEGATECALL transfers funds. Crossed-value CALL/CALLCODE fixtures confirm that Erigon, Reth and Nethermind use the explicit child value rather than the outer value. Besu still omits the nonzero-value child. The independent Geth draft implementation also matches these checks; it is not an independent vote for the policy.

## Decision needed

Review the inherited DELEGATECALL exception as a compatibility choice and extend to more precompiles/forks. The precompile-values corpus separates outer and child values, pre-funds zero-value creations with a preceding simulated transfer, and returns the call success bit. Parent error propagation remains a separate H24 issue.
