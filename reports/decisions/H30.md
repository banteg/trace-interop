# Omitted trace_filter range bounds

H30 · Spec decision / compatibility · [All decisions](../README.md#decisions-to-review)

**Status: ⚪ Under review** · [Status definitions](../../decisions/README.md#status-key)

No policy conclusion has been recorded. Implementation observations below do not establish client-team agreement.

## Recommendation

Default an omitted fromBlock to the earliest available block and an omitted toBlock to latest. Respect an explicitly supplied endpoint, then apply after/count to the ordered result over that full range.

A filter with only toBlock should reach earlier history, and an unbounded filter should not silently search only the head block. The captured chain has its first matching records in block 1 and head 48, so count: 3 exposes this default without relying on trace field formatting.

## Background

The pinned draft already describes an earliest-to-latest default. Both pinned Besu and Nethermind builds start at head 48; Erigon and Reth start at block 1. An explicit head-only query succeeds on all four. See the [live capture](../../evidence/2026-09-23/h30-code-review/README.md).
